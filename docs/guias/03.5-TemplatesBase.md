# Guia 03.5 — Templates base da aplicação

Neste passo vamos transformar os protótipos estáticos HTML/Tailwind do FloraHub em **templates Blade** integrados na aplicação Laravel.

Vamos construir três páginas:

1. **Página inicial pública** (Home);
2. **Painel do utilizador** (User Dashboard);
3. **Painel de administração** (Admin Dashboard).

O objetivo principal **não** é o conteúdo das páginas, mas sim a forma como se **organiza e reutiliza a estrutura visual** de uma aplicação:

```text
Layout
   ↓
Estrutura de interface reutilizável (cabeçalho, barra lateral, rodapé…)
   ↓
Página
   ↓
Conteúdo específico da página
```

No final teremos:

```text
resources/views/
│
├── layouts/
│   ├── public.blade.php        → layout público (cabeçalho + rodapé)
│   ├── dashboard.blade.php     → layout base da aplicação (barra lateral + barra superior)
│   ├── user.blade.php          → área do utilizador  (usa o dashboard)
│   └── admin.blade.php         → área de administração (usa o dashboard)
│
├── components/
│   └── stat-card.blade.php     → cartão de indicador reutilizável
│
├── home.blade.php              → página inicial
├── user/dashboard.blade.php    → painel do utilizador
└── admin/dashboard.blade.php   → painel de administração
```

## 0. Âmbito deste passo

Neste passo trabalhamos **apenas a camada de apresentação** (templates).

**Não** vamos implementar:

- login, registo ou alterações ao Fortify;
- papéis (`admin` / `user`) ou permissões;
- proteção de rotas por autenticação ou autorização;
- notificações funcionais;
- modelos, base de dados ou CRUD.

Todo o conteúdo dos painéis (nomes, números, listas) será **estático**, tal como nos protótipos.

> Os painéis de utilizador e de administração terão, por agora, rotas **públicas**. Não existe nenhum risco porque apenas mostram conteúdo fictício. A proteção destas áreas será feita num passo posterior, quando forem introduzidos autenticação e papéis.

A funcionalidade de autenticação criada pelo Starter Kit (login, registo, `/dashboard`, definições) **mantém-se intacta**. Não devemos alterá-la neste passo.

## 2. Conceitos Blade necessários

> Esta secção é uma **revisão rápida** do Guia 03.2 (componentes Blade). Se já o concluiu, pode lê-la na diagonal e avançar para a secção 3.

### 2.1. Componentes anónimos

Um **componente anónimo** é simplesmente um ficheiro Blade, sem classe PHP associada.

Por exemplo, o ficheiro:

```text
resources/views/components/stat-card.blade.php
```

pode ser usado em qualquer vista como:

```blade
<x-stat-card />
```

### 2.2. Layouts como componentes

Em Laravel, um **layout** é também um componente. A diferença é apenas o seu papel: define a estrutura HTML completa (`<html>`, `<head>`, `<body>`) e deixa um "buraco" onde cada página coloca o seu conteúdo.

Esse "buraco" chama-se **slot** e escreve-se:

```blade
{{ $slot }}
```

### 2.3. O namespace `layouts::`

O Starter Kit já utiliza layouts assim:

```blade
<x-layouts::app>
    ...
</x-layouts::app>
```

O prefixo `layouts::` está registado pelo Livewire 4 em `vendor/livewire/livewire/config/livewire.php`:

```php
'component_namespaces' => [
    'layouts' => resource_path('views/layouts'),
    'pages' => resource_path('views/pages'),
],
```

Isto significa que:

```text
<x-layouts::public>     →  resources/views/layouts/public.blade.php
<x-layouts::dashboard>  →  resources/views/layouts/dashboard.blade.php
```

Vamos aproveitar esta convenção já existente para os nossos layouts.

### 2.4. Props

**Props** são valores passados ao componente como atributos:

```blade
<x-layouts::public title="Início">
```

Dentro do componente, declaram-se com `@props` e ficam disponíveis como variáveis:

```blade
@props([
    'title' => 'Painel',   {{-- valor por omissão --}}
])

<h1>{{ $title }}</h1>
```

Atenção à diferença:

```blade
<x-layouts::dashboard dark="true">      {{-- $dark é a string "true" --}}
<x-layouts::dashboard :dark="true">     {{-- $dark é o booleano true (expressão PHP) --}}
```

O `:` antes do nome do atributo indica que o valor é uma **expressão PHP**.

### 2.5. Slots com nome (named slots)

Um componente pode ter vários "buracos". Além do `$slot` principal, podemos criar **slots com nome**:

```blade
{{-- Dentro do layout --}}
<nav>{{ $navigation }}</nav>
<main>{{ $slot }}</main>
```

```blade
{{-- Na página --}}
<x-layouts::exemplo>
    <x-slot:navigation>
        <a href="#">Início</a>
    </x-slot:navigation>

    <p>Isto vai para o $slot principal.</p>
</x-layouts::exemplo>
```

### 2.6. Comentários

```blade
<!-- Comentário HTML: é enviado para o browser -->
{{-- Comentário Blade: é removido e NÃO chega ao browser --}}
```

### 2.7. Criar vistas e componentes com Artisan

Neste guia vamos usar dois comandos Artisan para criar ficheiros Blade.

**`make:view`**: cria uma vista em `resources/views/`:

```bash
php artisan make:view home                →  resources/views/home.blade.php
php artisan make:view user.dashboard      →  resources/views/user/dashboard.blade.php
php artisan make:view layouts.public      →  resources/views/layouts/public.blade.php
```

O **ponto** no nome corresponde a uma **pasta**. Se a pasta não existir, o Artisan cria-a.

Usamos `make:view` para as **páginas** e para os **layouts**.

**`make:component --view`**: cria um componente anónimo em `resources/views/components/`:

```bash
php artisan make:component StatCard --view   →  resources/views/components/stat-card.blade.php
```

Usamos `make:component --view` para **componentes reutilizáveis** usados com `<x-nome>`.

Os dois comandos geram um ficheiro com um conteúdo de exemplo semelhante a:

```blade
<div>
    <!-- Uma citação aleatória -->
</div>
```

Este conteúdo serve apenas para confirmar que o ficheiro foi criado. **Deve ser sempre apagado** e substituído pelo código indicado no guia.

Para consultar todas as opções de um comando:

```bash
php artisan make:view --help
php artisan make:component --help
```

## 3. Preparar o tema visual

### 3.1. Protótipo (CDN) vs. aplicação (Vite)

Nos protótipos o Tailwind é carregado por CDN e as cores da marca são definidas em JavaScript:

```html
<script src="https://cdn.tailwindcss.com"></script>
<script>
    tailwind.config = {
        theme: { extend: { colors: { brand: { 50: '#f4f7f2', ... } } } },
    };
</script>
```

Isto é útil para prototipar, **mas não se usa na aplicação**. No Laravel, o Tailwind CSS 4 é compilado pelo **Vite** a partir de:

```text
resources/css/app.css
```

e as cores personalizadas definem-se em CSS, dentro do bloco `@theme`.

Notar também, no início de `app.css`:

```css
@source '../views';
```

Esta linha indica ao Tailwind que deve procurar classes em todos os ficheiros de `resources/views`. É por isso que as classes que escrevemos nas vistas Blade são incluídas no CSS final.

### 3.2. As cores `brand`

As cores `brand` já foram acrescentadas ao `@theme` de `resources/css/app.css` no [Guia 03.1](03.1-ConceitosTailwind.md), secção 2. Confirmar que existem as 11 variáveis `--color-brand-50` a `--color-brand-950`.

**Exercício:** comparar os valores com o `tailwind.config` do protótipo e confirmar que são iguais.

### 3.3. Nome da aplicação

No ficheiro `.env` (e também em `.env.example`) confirmar:

```env
APP_NAME=FloraHub
```

Este valor é usado no título das páginas através de `config('app.name')`.

### 3.4. Logótipo

O Starter Kit tem um componente com o ícone do logótipo:

```text
resources/views/components/app-logo-icon.blade.php
```

Neste momento contém o logótipo do Laravel. Substituir **todo** o conteúdo pelo ícone (folha) usado nos protótipos:

```blade
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="currentColor" {{ $attributes }}>
    <path d="M12 21C7 21 3 17 3 11.5 3 6 7.5 3 12 3c1 4 5 5.5 5 10.5S15 21 12 21Z" />
</svg>
```

Repare em `{{ $attributes }}`: permite que quem usa o componente defina classes, por exemplo:

```blade
<x-app-logo-icon class="h-5 w-5" />
```

Nos protótipos, este SVG da folha aparece **várias vezes** (cabeçalho, rodapé, barra lateral, menu). A partir de agora passamos a usar sempre `<x-app-logo-icon>`, o nosso primeiro exemplo de **reutilização**.

## 4. Layout público

### 4.1. Criar o ficheiro

Criar a vista do layout com o Artisan:

```bash
php artisan make:view layouts.public
```

Resultado esperado:

```text
INFO  View [resources/views/layouts/public.blade.php] created successfully.
```

Abrir o ficheiro criado, **apagar todo o conteúdo gerado** (`<div>` com a citação) e substituir pela seguinte estrutura base:

```blade
<!DOCTYPE html>
<html lang="pt">
    <head>
        @include('partials.head')
    </head>
    <body class="bg-stone-50 font-sans text-stone-800 antialiased">

        <!-- Cabeçalho -->
        {{-- (4.3) colar aqui o <header> de home.html --}}

        <!-- Conteúdo da página -->
        <main>
            {{ $slot }}
        </main>

        <!-- Rodapé -->
        {{-- (4.4) colar aqui o <footer> de home.html --}}

    </body>
</html>
```

### 4.2. Porquê `@include('partials.head')`?

Abrir `resources/views/partials/head.blade.php` (já existe no Starter Kit). Contém:

- as `<meta>` tags;
- o `<title>` construído a partir de `$title` e `config('app.name')`;
- os favicons;
- `@vite([...])`, que carrega o CSS e o JavaScript compilados pelo Vite.

Em vez de copiarmos o `<head>` do protótipo (que usa o CDN do Tailwind), **reutilizamos** o `<head>` que a aplicação já tem. Assim, todas as páginas carregam os mesmos recursos.

> Como `partials.head` usa a variável `$title`, qualquer página que passe `title="..."` ao layout terá o título correto no separador do browser, por exemplo **"Início - FloraHub"**.

### 4.3. Cabeçalho

Copiar de `home.html` o bloco `<header> … </header>` (linhas 27–61) para o local indicado.

Depois de colado, fazer as seguintes **adaptações**:

| No protótipo                           | Na aplicação                     |
|----------------------------------------|----------------------------------|
| `href="home.html"`                     | `href="{{ route('home') }}"`     |
| `href="login.html"`                    | `href="{{ route('login') }}"`    |
| `href="register.html"`                 | `href="{{ route('register') }}"` |
| `href="species-index.html"`            | `href="#"` (página ainda não existe) |
| `<svg …><path d="M12 21C7 …"/></svg>`  | `<x-app-logo-icon class="h-5 w-5" />` |

Exemplo do logótipo, **antes**:

```html
<a href="home.html" class="flex items-center gap-2">
    <span class="flex h-9 w-9 items-center justify-center rounded-lg bg-brand-600 text-white">
        <svg class="h-5 w-5" viewBox="0 0 24 24" fill="currentColor"><path d="M12 21C7 21 3 17 3 11.5 3 6 7.5 3 12 3c1 4 5 5.5 5 10.5S15 21 12 21Z"/></svg>
    </span>
    <span class="text-lg font-semibold tracking-tight text-stone-900">FloraHub</span>
</a>
```

**depois**:

```blade
<a href="{{ route('home') }}" class="flex items-center gap-2">
    <span class="flex h-9 w-9 items-center justify-center rounded-lg bg-brand-600 text-white">
        <x-app-logo-icon class="h-5 w-5" />
    </span>
    <span class="text-lg font-semibold tracking-tight text-stone-900">FloraHub</span>
</a>
```

> As rotas `login` e `register` já existem (foram criadas pelo Fortify). Estamos apenas a **ligar** para elas. Não estamos a alterar a autenticação.

> Porque usar `route('home')` em vez de escrever `/`? Se o URL de uma rota mudar, basta alterar `routes/web.php`; todos os links continuam corretos porque usam o **nome** da rota.

O menu móvel (`<details class="md:hidden">`) funciona sem JavaScript: o elemento HTML `<details>` abre e fecha nativamente. Mantemo-lo tal como está no protótipo.

### 4.4. Rodapé

Copiar de `home.html` o bloco `<footer> … </footer>` (linhas 211–242) e aplicar as **mesmas adaptações** da tabela anterior (links e logótipo, aqui com `class="h-4 w-4"`).

Adicionalmente, substituir o ano fixo:

```html
© 2026 FloraHub — projeto educativo.
```

por:

```blade
© {{ date('Y') }} FloraHub — projeto educativo.
```

### 4.5. Verificar

O layout ainda não é usado por nenhuma página. Confirmar apenas que:

- não existem `href="….html"` no ficheiro;
- o SVG da folha foi substituído por `<x-app-logo-icon>` em todas as ocorrências;
- existe **um** `{{ $slot }}` dentro de `<main>`.

## 5. Página inicial (Home)

### 5.1. Criar a vista

Criar a vista da página inicial:

```bash
php artisan make:view home
```

Foi criado:

```text
resources/views/home.blade.php
```

Apagar o conteúdo gerado e substituir por:

```blade
<x-layouts::public title="Início">

    {{-- colar aqui o conteúdo de <main> de home.html (sem as tags <main> e </main>) --}}

</x-layouts::public>
```

Copiar de `home.html` **tudo o que está dentro** de `<main>` (linhas 64–207): as secções *Hero*, *Featured species*, *Features* e *CTA banner*.

Aplicar novamente a tabela de adaptações de links (4.3):

- `species-index.html` e `species-show.html` → `#`;
- `register.html` → `{{ route('register') }}`.

**Exercício:** traduzir os comentários HTML das secções para português (ex.: `<!-- Hero -->` → `<!-- Destaque principal -->`).

Notar que a página **não tem** `<html>`, `<head>`, `<header>` nem `<footer>`: tudo isso vem do layout. A página contém **apenas o seu conteúdo específico**.

### 5.2. Alterar a rota

Abrir `routes/web.php`. A rota `/` aponta para a vista `welcome` do Starter Kit:

```php
Route::view('/', 'welcome')->name('home');
```

Alterar para:

```php
Route::view('/', 'home')->name('home');
```

`Route::view()` é o atalho do Laravel para rotas que apenas **mostram uma vista**, sem necessidade de controlador.

Notar que o **nome** da rota (`home`) não muda. Por isso todos os links `route('home')` existentes (incluindo os do Starter Kit) continuam a funcionar.

Confirmar a rota com o Artisan:

```bash
php artisan route:list --name=home
```

Resultado esperado:

```text
GET|HEAD  /  ........  home
```

### 5.3. Remover a vista `welcome`

A vista `resources/views/welcome.blade.php` deixa de ser usada. Confirmar que não há outras referências a `'welcome'`:

**macOS / Linux**

```bash
grep -rn "'welcome'" routes resources app
```

**Windows PowerShell**

```powershell
Select-String -Path routes\*.php, app\*.php -Pattern "'welcome'"
Get-ChildItem resources -Recurse -File | Select-String -Pattern "'welcome'"
```

(Em alternativa, usar a pesquisa global do PHPStorm: `Ctrl+Shift+F` / `Cmd+Shift+F`.)

Se não existirem resultados, remover o ficheiro com o Git (funciona em qualquer sistema operativo):

```bash
git rm resources/views/welcome.blade.php
```

### 5.4. Verificar

Iniciar a aplicação (se ainda não estiver em execução):

```bash
composer run dev
```

Abrir `http://localhost:8000/` e confirmar:

- [ ] a página tem o aspeto de `home.html`;
- [ ] o cabeçalho e o rodapé aparecem;
- [ ] o separador do browser mostra **"Início - FloraHub"**;
- [ ] "Iniciar sessão" abre a página de login do Starter Kit;
- [ ] "Criar conta" abre a página de registo;
- [ ] em largura reduzida aparece o menu móvel (☰).

**Exercício:** abrir o código-fonte da página no browser (Ctrl+U / Cmd+Option+U) e identificar onde termina o layout e começa o conteúdo de `home.blade.php`.

## 6. Layout base da aplicação

Os dois painéis partilham a **mesma estrutura**:

```text
┌──────────────┬───────────────────────────────────────┐
│              │  Barra superior (título + ações)      │
│   Barra      ├───────────────────────────────────────┤
│   lateral    │                                       │
│  (logótipo,  │         Conteúdo da página            │
│   menu,      │              ($slot)                  │
│  utilizador) │                                       │
└──────────────┴───────────────────────────────────────┘
```

Mas **variam** em:

| Elemento                        | Utilizador               | Administração                  |
|---------------------------------|--------------------------|--------------------------------|
| Cor da barra lateral            | clara (`bg-white`)       | escura (`bg-stone-900`)        |
| Etiqueta junto ao logótipo      | —                        | "Administração"                |
| Links do menu                   | Painel, Plantas, …       | Painel, Espécies, …            |
| Rodapé da barra lateral         | Sofia Almeida            | Rui Mendes + Terminar sessão   |
| Subtítulo na barra superior     | —                        | "Administração"                |
| Notificações e menu do perfil   | conteúdos diferentes     | conteúdos diferentes           |

Estratégia:

- tudo o que é **igual** fica no layout `dashboard`;
- tudo o que **varia** entra por **props** (valores simples) ou **named slots** (blocos de HTML).

### 6.1. Criar o layout

Criar a vista do layout base:

```bash
php artisan make:view layouts.dashboard
```

Foi criado:

```text
resources/views/layouts/dashboard.blade.php
```

### 6.2. Analisar o layout

Comparar este ficheiro com `user-dashboard.html` e `admin-dashboard.html`. Identificar:

**Props** (valores simples):

| Prop       | Utilização                                                        |
|------------|-------------------------------------------------------------------|
| `title`    | título na barra superior **e** no separador do browser (`partials.head`) |
| `subtitle` | texto pequeno acima do título (só aparece se tiver valor — `@if`) |
| `dark`     | escolhe o tema claro ou escuro da barra lateral                   |

**Slots** (blocos de HTML):

| Slot              | Onde aparece                                   | Obrigatório? |
|-------------------|------------------------------------------------|--------------|
| `$slot`           | dentro de `<main>` — conteúdo da página        | sim          |
| `$navigation`     | menu da barra lateral **e** menu móvel         | sim          |
| `$sidebarFooter`  | fundo da barra lateral (utilizador)            | sim          |
| `$actions`        | lado direito da barra superior                 | sim          |
| `$brandBadge`     | junto ao logótipo                              | não (`?? ''`) |

Pontos importantes:

1. **`$navigation` é impresso duas vezes**: na barra lateral (desktop) e no menu `<details>` (móvel). O mesmo HTML é escrito uma única vez pela área e reutilizado em dois sítios. No protótipo, os links estavam duplicados.

2. **`{{ $brandBadge ?? '' }}`**: o operador `??` torna o slot opcional. Se a área não definir este slot, não é mostrado nada. Os restantes slots com nome são obrigatórios: se faltarem, o Blade gera um erro de variável indefinida.

3. **`@class([...])`**: constrói o atributo `class` de forma condicional.

   ```blade
   <aside @class([
       'hidden w-64 flex-none flex-col lg:flex',        {{-- sempre aplicadas --}}
       'border-r border-stone-200 bg-white' => ! $dark,  {{-- só se $dark for false --}}
       'bg-stone-900' => $dark,                          {{-- só se $dark for true  --}}
   ])>
   ```

   Com `$dark = false` o resultado é:

   ```html
   <aside class="hidden w-64 flex-none flex-col lg:flex border-r border-stone-200 bg-white">
   ```

> **Importante:** `dark` é apenas uma opção **visual**. O layout não sabe nada sobre utilizadores, papéis ou permissões, nem deve saber.

## 9. Componente `stat-card`

No painel do utilizador existem **quatro** cartões de indicadores com o mesmo HTML. No painel de administração existem mais quatro. Apenas mudam:

- o texto (ex.: "As minhas plantas");
- o valor (ex.: `12`);
- as cores do ícone (ex.: `bg-brand-100 text-brand-700`);
- o ícone (SVG).

Este é um bom candidato para um **componente**.

> Nem tudo deve ser componente. Uma secção que aparece só uma vez, ou cuja estrutura varia muito, fica mais legível escrita diretamente na página. Criamos componentes quando o **mesmo bloco se repete**.

### 9.1. Criar o componente

Criar um componente **anónimo** com o Artisan:

```bash
php artisan make:component StatCard --view
```

Resultado esperado:

```text
INFO  View [resources/views/components/stat-card.blade.php] created successfully.
```

Notar:

- o nome é indicado em *PascalCase* (`StatCard`) e o ficheiro é criado em *kebab-case* (`stat-card.blade.php`);
- a opção `--view` cria **apenas a vista**, sem classe PHP. É isto que torna o componente **anónimo**;
- sem `--view`, o Artisan criaria também uma classe em `app/View/Components/StatCard.php`, que não é necessária porque o componente não tem lógica.

> Atenção: **não** usar `make:component` para os layouts. Os layouts ficam em `resources/views/layouts/` (namespace `layouts::`) e foram criados com `make:view`. O `make:component --view` cria sempre o ficheiro em `resources/views/components/`, usado com `<x-nome>`.

Abrir o ficheiro criado, apagar o conteúdo gerado e substituir por:

```blade
@props([
    'label',
    'value',
    'iconClass' => 'bg-brand-100 text-brand-700',
])

<div class="rounded-2xl border border-stone-200 bg-white p-6 shadow-sm">
    <div class="flex items-center justify-between">
        <p class="text-sm text-stone-500">{{ $label }}</p>
        <span class="flex h-8 w-8 items-center justify-center rounded-lg {{ $iconClass }}">
            {{ $slot }}
        </span>
    </div>
    <p class="mt-2 text-3xl font-semibold text-stone-900">{{ $value }}</p>
</div>
```

Notar:

- `label` e `value` não têm valor por omissão, por isso **devem** ser indicados;
- `iconClass` tem valor por omissão (cores da marca);
- o **SVG do ícone** entra pelo `$slot`.

> Em `@props` o nome é escrito em *camelCase* (`iconClass`), mas no atributo HTML usa-se *kebab-case* (`icon-class`). O Blade converte automaticamente.

### 9.2. Substituir os cartões

| Barra lateral, barra superior, menu móvel | `layouts/dashboard` | área do utilizador e de administração |
| Menu e utilizador de cada área      | `layouts/user`, `layouts/admin` | páginas de cada área   |
| Cartão de indicador                 | `components/stat-card` | os dois painéis              |
| Logótipo                            | `components/app-logo-icon` | todos os layouts          |

### 12.3. O que continua estático

- nomes dos utilizadores ("Sofia Almeida", "Rui Mendes") e respetivas iniciais;
- todos os números dos indicadores;
- lembretes, atividade, plantas, espécies e paginação;
- notificações;
- links para páginas ainda inexistentes (`#`), incluindo "Terminar sessão", "Perfil" e "Definições".

Estes elementos serão ligados a dados reais e à autenticação em passos posteriores.

### 12.4. Conceitos trabalhados

| Conceito                   | Onde foi usado                                          |
|----------------------------|---------------------------------------------------------|
| Layout como componente     | `<x-layouts::public>`, `<x-layouts::dashboard>`         |
| `{{ $slot }}`              | conteúdo de cada página                                 |
| Named slots                | `navigation`, `sidebarFooter`, `actions`, `brandBadge`  |
| Props com `@props`         | `title`, `subtitle`, `dark`, `label`, `value`, `iconClass` |
| `:atributo` (expressão PHP) | `:title="$title"`, `:dark="true"`                      |
| Layouts encadeados         | `user` → `dashboard`, `admin` → `dashboard`             |
| `@include`                 | `partials.head`                                         |
| `@class`                   | tema claro/escuro, link ativo                           |
| `route()` e rotas com nome | todos os links internos                                 |
| `request()->routeIs()`     | destacar o link ativo                                   |
| `Route::view()`            | rotas das três páginas                                  |
| Tema Tailwind 4 (`@theme`) | cores `brand`                                           |
| Artisan `make:view`        | layouts e páginas                                       |
| Artisan `make:component --view` | componente `stat-card`                             |

## 13. Problemas comuns

| Sintoma | Causa provável | Solução |
|---------|----------------|---------|
| A página aparece **sem estilos** ou sem as cores `brand` | O Vite não está em execução | Confirmar que `composer run dev` está a correr. Em alternativa, executar `npm run build` |
| As cores `brand-*` não aparecem, mas as restantes sim | Cores não adicionadas ao `@theme` | Rever o passo 3.2 e guardar `resources/css/app.css` |
| Aparece uma **citação** (ex.: "Live as if…") na página | O conteúdo gerado pelo `make:view` não foi apagado | Apagar o `<div>` gerado no ficheiro indicado |
| `View [home] not found.` | Vista criada com nome ou pasta errados | Confirmar que o ficheiro existe em `resources/views/home.blade.php`. Voltar a criar com `php artisan make:view home` |
| `Unable to locate a class or view for component [layouts::public]` | O layout não está em `resources/views/layouts/` | Confirmar a localização. O layout deve ser criado com `php artisan make:view layouts.public` e **não** com `make:component` |
| `Unable to locate a class or view for component [stat-card]` | O componente não está em `resources/views/components/` | Criar com `php artisan make:component StatCard --view` |
| `Undefined variable $navigation` (ou `$sidebarFooter`, `$actions`) | Falta um slot com nome no layout da área | Confirmar que `layouts/user.blade.php` (ou `admin`) define `<x-slot:navigation>`, `<x-slot:sidebarFooter>` e `<x-slot:actions>` |
| O conteúdo da página não aparece, mas o layout sim | Falta `{{ $slot }}` no layout da área | Confirmar que `layouts/user.blade.php` (ou `admin`) tem `{{ $slot }}` antes de `</x-layouts::dashboard>` |
| `Route [user.dashboard] not defined.` | Rota não criada ou com nome diferente | Rever `routes/web.php` e executar `php artisan route:list --name=dashboard` |
| O logótipo continua a ser o do Laravel | O componente `app-logo-icon` não foi alterado | Rever o passo 3.4 |
| O título do separador mostra "Laravel" | `APP_NAME` não foi alterado ou a configuração está em cache | Alterar `APP_NAME=FloraHub` no `.env` e executar `php artisan config:clear` |
| As alterações numa vista não aparecem | Vistas compiladas em cache | Executar `php artisan view:clear` e recarregar a página |
