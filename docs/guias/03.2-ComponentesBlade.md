# Guia 03.2 — Componentes Blade

No [Guia 03.1](03.1-ConceitosTailwind.md) vimos que um simples botão ou _badge_ pode ter 7 ou 8 classes Tailwind. Se o repetirmos em 20 páginas, alterar o aspeto obriga a editar 20 sítios.

Neste guia aprendemos a resolver este problema com **componentes Blade**: pedaços de HTML reutilizáveis, com parâmetros, que usamos como se fossem etiquetas HTML novas:

```blade
<x-badge color="red">Removida</x-badge>
```

Vamos construir, na página de testes `/dev/components`:

| Componente   | Para quê                                   | Conceito principal                      |
|--------------|--------------------------------------------|-----------------------------------------|
| `x-badge`    | etiqueta colorida                          | `@props` e `$slot`                      |
| `x-card`     | cartão com cabeçalho e rodapé opcionais    | _slots_ com nome                        |
| `x-button`   | botão ou link com variantes                | `$attributes`, `@class`, `match`        |
| `x-ui.alert` | caixa de aviso                             | componentes em subpastas                |

A teoria de apoio está no tutorial [Componentes Blade](../tutorials/03.Components.md).

No final teremos:

```text
resources/views/
│
├── components/
│   ├── badge.blade.php
│   ├── card.blade.php
│   ├── button.blade.php
│   └── ui/
│       └── alert.blade.php
│
└── dev/
    └── components.blade.php      → página de testes dos componentes
```

## Antes de começar

### Como utilizar este guia

Este guia foi escrito para ser seguido **de forma autónoma**, depois da aula.

- Seguir as secções **pela ordem indicada**.
- Os ficheiros novos são criados com **comandos Artisan**. Não criar ficheiros manualmente.
- No fim de cada secção existe um bloco **Verificar**.
- Se algo não funcionar, consultar a secção [10. Problemas comuns](#10-problemas-comuns).

### Pré-requisitos

- **Guia 03.1** concluído (existem `layouts/dev.blade.php`, a rota `dev.tailwind` e as cores `brand-*`).
- Serviços Docker e aplicação em execução:

  ```bash
  docker compose up -d
  composer run dev
  ```

- Os comandos `php artisan …` são executados noutro terminal, **na raiz do projeto**.

### Âmbito

Aprendemos componentes **anónimos** (apenas um ficheiro `.blade.php`, sem classe PHP). São suficientes para o FloraHub.

## 1. Preparar a página de testes

⏱ ~3 min

```bash
php artisan make:view dev.components
```

Resultado esperado:

```text
INFO  View [resources/views/dev/components.blade.php] created successfully.
```

Apagar o conteúdo gerado e substituir por:

```blade
<x-layouts::dev title="Componentes">
    <div class="space-y-16">

        <h1 class="text-3xl font-bold tracking-tight text-stone-900">Laboratório de Componentes</h1>

        {{-- As secções seguintes são acrescentadas aqui --}}

    </div>
</x-layouts::dev>
```

Em `routes/web.php`, dentro do grupo `dev.`, acrescentar a rota:

```php
Route::prefix('dev')->name('dev.')->group(function () {
    Route::view('tailwind', 'dev.tailwind')->name('tailwind');
    Route::view('components', 'dev.components')->name('components');
});
```

### Verificar

- http://localhost:8000/dev/components mostra o título.
- A barra superior tem agora os links **Tailwind** e **Componentes**.

## 2. O primeiro componente: `x-badge`

⏱ ~10 min

### 2.1. O problema: repetição

Acrescentar à página:

```blade
<section class="space-y-4">
    <h2 class="text-xl font-semibold text-stone-900">2. x-badge</h2>

    <div class="flex flex-wrap gap-2">
        <span class="inline-flex items-center rounded-full bg-brand-100 px-2.5 py-0.5 text-xs font-medium text-brand-800">Ativa</span>
        <span class="inline-flex items-center rounded-full bg-brand-100 px-2.5 py-0.5 text-xs font-medium text-brand-800">Pública</span>
        <span class="inline-flex items-center rounded-full bg-red-100 px-2.5 py-0.5 text-xs font-medium text-red-800">Removida</span>
    </div>
</section>
```

As mesmas 7 classes repetem-se. Vamos extraí-las para um componente.

### 2.2. Criar o componente

```bash
php artisan make:component Badge --view
```

Resultado esperado:

```text
INFO  View [resources/views/components/badge.blade.php] created successfully.
```

A opção `--view` cria um componente **anónimo** (só o ficheiro Blade). Sem ela, o Artisan cria também uma classe PHP, de que não precisamos.

> O nome `Badge` (PascalCase) gera o ficheiro `badge.blade.php` e a etiqueta `<x-badge>`. Um nome composto como `StatCard` gera `stat-card.blade.php` e `<x-stat-card>`.

Substituir o conteúdo de `resources/views/components/badge.blade.php` por:

```blade
@props(['color' => 'brand'])

<span {{ $attributes->class([
    'inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-medium',
    'bg-brand-100 text-brand-800' => $color === 'brand',
    'bg-red-100 text-red-800' => $color === 'red',
    'bg-amber-100 text-amber-800' => $color === 'amber',
]) }}>
    {{ $slot }}
</span>
```

- `@props([...])` declara as **propriedades** do componente e os valores por omissão. `color` é opcional e vale `brand`.
- `{{ $slot }}` é o **conteúdo** escrito entre as etiquetas de abertura e fecho.
- `$attributes->class([...])` junta classes fixas com classes **condicionais** (`'classes' => condição`). Já vimos esta ideia com `@class` no Guia 03.1.

### 2.3. Usar o componente

Na página, substituir o `<div class="flex flex-wrap gap-2">` por:

```blade
<div class="flex flex-wrap gap-2">
    <x-badge>Ativa</x-badge>
    <x-badge>Pública</x-badge>
    <x-badge color="red">Removida</x-badge>
    <x-badge color="amber">Pendente</x-badge>
</div>
```

### 2.4. Props estáticas e dinâmicas

Há duas formas de passar valores:

```blade
<x-badge color="red">…</x-badge>          {{-- texto fixo: "red" --}}
<x-badge :color="$cor">…</x-badge>        {{-- expressão PHP: o valor da variável $cor --}}
```

O prefixo `:` significa "o que se segue é PHP". Acrescentar, dentro da mesma `<section>`:

```blade
    @php
        $estados = ['Ativa' => 'brand', 'Pendente' => 'amber', 'Removida' => 'red'];
    @endphp

    <div class="flex flex-wrap gap-2">
        @foreach ($estados as $nome => $cor)
            <x-badge :color="$cor">{{ $nome }}</x-badge>
        @endforeach
    </div>
```

### Exercício

1. Acrescentar a cor `sky` ao componente e usá-la: `<x-badge color="sky">Info</x-badge>`.
2. Alterar **uma única** linha do componente (por exemplo, `px-2.5` → `px-4`). O que acontece a **todos** os _badges_?

### Verificar

- Aparecem sete _badges_ (quatro + três do `@foreach`), os primeiros iguais aos da versão sem componente.
- Alterar o componente altera todos de uma vez.

## 3. Atributos: `$attributes`

⏱ ~7 min

Quem usa um componente pode passar **qualquer atributo HTML** (`class`, `id`, `title`, `data-*`, `wire:*`, …). Eles chegam ao componente na variável `$attributes`, e o componente decide onde os colocar.

Acrescentar:

```blade
<section class="space-y-4">
    <h2 class="text-xl font-semibold text-stone-900">3. Atributos</h2>

    <div class="flex flex-wrap items-center gap-2">
        <x-badge class="uppercase tracking-wide">uppercase</x-badge>
        <x-badge class="px-4 py-2 text-sm" color="amber">maior</x-badge>
        <x-badge id="meu-badge" title="Passe o rato" data-origem="teste">id + title + data-*</x-badge>
    </div>
</section>
```

Inspecionar o último _badge_ nas DevTools: o `<span>` tem `id`, `title` e `data-origem`, que **não** estão declarados no componente. Foi o `{{ $attributes->class(…) }}` que os colocou lá.

| Expressão                              | Efeito                                                        |
|----------------------------------------|---------------------------------------------------------------|
| `{{ $attributes }}`                    | imprime todos os atributos recebidos                          |
| `{{ $attributes->class([…]) }}`        | idem, juntando classes condicionais às recebidas              |
| `{{ $attributes->merge(['type' => 'button']) }}` | idem, com **valores por omissão** para outros atributos |

> **Atributo ou prop?** Se o nome está em `@props`, **deixa de estar** em `$attributes` (é uma variável própria). Tudo o resto fica em `$attributes`.

> O componente `resources/views/components/app-logo-icon.blade.php` do Starter Kit faz exatamente isto: `<svg … {{ $attributes }}>`, por isso podemos escrever `<x-app-logo-icon class="h-5 w-5" />`.

### Exercício

Passar `onclick="alert('olá')"` a um `<x-badge>`. Funciona? Porquê?

### Verificar

- Os dois primeiros _badges_ mudam de aspeto só com `class`.
- O terceiro tem `id`, `title` e `data-origem` no HTML.

## 4. Slots com nome: `x-card`

⏱ ~8 min

O `$slot` é o conteúdo **por omissão**. Quando o componente tem várias zonas (cabeçalho, corpo, rodapé), usamos **slots com nome**.

```bash
php artisan make:component Card --view
```

Substituir o conteúdo de `resources/views/components/card.blade.php` por:

```blade
<div {{ $attributes->class('rounded-xl border border-stone-200 bg-white shadow-sm') }}>
    @isset($header)
        <div class="border-b border-stone-200 px-5 py-3 font-semibold text-stone-900">
            {{ $header }}
        </div>
    @endisset

    <div class="p-5">
        {{ $slot }}
    </div>

    @isset($footer)
        <div class="border-t border-stone-200 bg-stone-50 px-5 py-3 text-sm text-stone-600">
            {{ $footer }}
        </div>
    @endisset
</div>
```

- Cada slot com nome é uma variável (`$header`, `$footer`).
- `@isset($header)` mostra a zona **só se** o slot foi passado.

Acrescentar à página:

```blade
<section class="space-y-4">
    <h2 class="text-xl font-semibold text-stone-900">4. x-card</h2>

    <div class="grid gap-6 md:grid-cols-3">
        <x-card>
            Só com o conteúdo por omissão.
        </x-card>

        <x-card>
            <x-slot:header>Rosaceae</x-slot:header>
            Família das rosas, macieiras e morangueiros.
        </x-card>

        <x-card>
            <x-slot:header>Rosaceae <x-badge>Ativa</x-badge></x-slot:header>
            Cartão completo.
            <x-slot:footer>12 espécies registadas</x-slot:footer>
        </x-card>
    </div>
</section>
```

Repare que o conteúdo fora de `<x-slot:…>` vai para `$slot`, e que **componentes se podem usar dentro de componentes** (`<x-badge>` dentro do cabeçalho).

### Exercício

1. Passar `class="border-brand-300 bg-brand-50"` a um dos cartões. O que acontece? (Atenção: `border-stone-200` e `border-brand-300` entram em conflito. Qual ganha? Ver o tutorial, secção "Conflito de classes".)
2. Acrescentar um slot `$actions` com dois botões no rodapé, alinhados à direita.

### Verificar

- O primeiro cartão só tem corpo; o segundo tem cabeçalho; o terceiro tem cabeçalho, corpo e rodapé.

## 5. Variantes e lógica: `x-button`

⏱ ~7 min

Um componente pode ter lógica PHP: escolher classes conforme uma _prop_ e até **mudar de etiqueta HTML**.

```bash
php artisan make:component Button --view
```

Substituir o conteúdo de `resources/views/components/button.blade.php` por:

```blade
@props(['variant' => 'primary', 'href' => null])

@php
    $variants = match ($variant) {
        'secondary' => 'border border-stone-300 bg-white text-stone-800 hover:bg-stone-50',
        'danger' => 'bg-red-600 text-white hover:bg-red-700',
        default => 'bg-brand-600 text-white hover:bg-brand-700',
    };
@endphp

@if ($href)
    <a href="{{ $href }}" {{ $attributes->class(['inline-flex items-center rounded-lg px-4 py-2 text-sm font-semibold transition', $variants]) }}>
        {{ $slot }}
    </a>
@else
    <button {{ $attributes->class(['inline-flex items-center rounded-lg px-4 py-2 text-sm font-semibold transition', $variants])->merge(['type' => 'button']) }}>
        {{ $slot }}
    </button>
@endif
```

- `match` escolhe o conjunto de classes conforme `$variant`.
- Com `href`, o componente gera um `<a>`; sem ele, um `<button>`.
- `->merge(['type' => 'button'])` dá `type="button"` **por omissão**, mas quem usa pode sobrepor (`type="submit"`).
- As classes aparecem **por extenso** dentro do `match`. Se as construíssemos com variáveis, o Tailwind não as encontraria (Guia 03.1, secção 8.3).

Acrescentar à página:

```blade
<section class="space-y-4">
    <h2 class="text-xl font-semibold text-stone-900">5. x-button</h2>

    <div class="flex flex-wrap items-center gap-3">
        <x-button>Guardar</x-button>
        <x-button variant="secondary">Cancelar</x-button>
        <x-button variant="danger">Eliminar</x-button>
        <x-button href="{{ route('dev.tailwind') }}">Ir para Tailwind (link)</x-button>
        <x-button type="submit" class="w-48 justify-center">type="submit"</x-button>
    </div>
</section>
```

### Exercício

1. Acrescentar uma variante `ghost` (sem fundo: `text-stone-700 hover:bg-stone-100`).
2. Inspecionar nas DevTools: qual é a etiqueta HTML do botão "Ir para Tailwind"? E dos outros?

### Verificar

- Três botões com cores diferentes; o quarto é um **link** com aspeto de botão; o último é largo e tem `type="submit"` no HTML.

## 6. Subpastas: `x-ui.alert`

⏱ ~4 min

Quando há muitos componentes, organizamo-los em **subpastas**. O ponto na etiqueta corresponde a uma pasta.

```bash
php artisan make:component Ui/Alert --view
```

Resultado esperado:

```text
INFO  View [resources/views/components/ui/alert.blade.php] created successfully.
```

| Ficheiro                                       | Etiqueta        |
|------------------------------------------------|-----------------|
| `components/badge.blade.php`                   | `<x-badge>`     |
| `components/ui/alert.blade.php`                | `<x-ui.alert>`  |
| `components/forms/input.blade.php` (exemplo)   | `<x-forms.input>` |

Substituir o conteúdo de `resources/views/components/ui/alert.blade.php` por:

```blade
@props(['type' => 'info', 'title' => null])

@php
    $styles = match ($type) {
        'success' => 'border-brand-200 bg-brand-50 text-brand-800',
        'error' => 'border-red-200 bg-red-50 text-red-800',
        default => 'border-sky-200 bg-sky-50 text-sky-800',
    };
@endphp

<div role="alert" {{ $attributes->class(['rounded-lg border p-4 text-sm', $styles]) }}>
    @if ($title)
        <p class="font-semibold">{{ $title }}</p>
    @endif

    <div>{{ $slot }}</div>
</div>
```

Acrescentar à página:

```blade
<section class="space-y-4">
    <h2 class="text-xl font-semibold text-stone-900">6. x-ui.alert</h2>

    <x-ui.alert>Mensagem informativa (tipo por omissão).</x-ui.alert>
    <x-ui.alert type="success" title="Guardado">A família foi criada com sucesso.</x-ui.alert>
    <x-ui.alert type="error" title="Erro">Não foi possível guardar. <x-badge color="red">422</x-badge></x-ui.alert>
</section>
```

### Exercício

Acrescentar um tipo `warning` (âmbar) ao alerta e usá-lo.

### Verificar

- Aparecem três alertas: azul, verde e vermelho.

## 7. Os layouts também são componentes

⏱ ~3 min

Desde o Guia 03.1 que usamos `<x-layouts::dev title="…">`. Isto é um componente anónimo que vive em `resources/views/layouts/dev.blade.php`:

```blade
<x-layouts::dev title="Componentes">
    …conteúdo da página…    ← vai para {{ $slot }} do layout
</x-layouts::dev>
```

- `layouts::` é um **espaço de nomes**: aponta para a pasta `resources/views/layouts/`.
- O atributo `title` chega ao layout como variável `$title` (o `partials.head` usa-a no `<title>` do separador).
- O conteúdo entre as etiquetas chega ao layout em `{{ $slot }}`.

É exatamente a mesma mecânica de `x-card`. No Guia 03.5 vamos criar layouts com **slots com nome** (`<x-slot:navigation>`, `<x-slot:actions>`), tal como o cartão da secção 4.

### Exercício

1. Alterar o `title` da página de testes e verificar o separador do navegador.
2. Que diferença há entre `<x-layouts::dev>` e `<x-dev>`? (Pista: onde procura o Laravel cada um?)

## 9. Resumo

| Conceito              | Exemplo                                                         |
|-----------------------|-----------------------------------------------------------------|
| Criar componente      | `php artisan make:component Badge --view`                       |
| Usar componente       | `<x-badge color="red">Texto</x-badge>`                          |
| Props com defaults    | `@props(['color' => 'brand'])`                                  |
| Prop dinâmica         | `:color="$cor"`                                                 |
| Conteúdo              | `{{ $slot }}`                                                   |
| Slots com nome        | `<x-slot:header>…</x-slot:header>` e `{{ $header }}`            |
| Slot opcional         | `@isset($footer)`                                               |
| Atributos             | `{{ $attributes }}`, `{{ $attributes->class([…]) }}`, `->merge([…])` |
| Subpastas             | `components/ui/alert.blade.php` → `<x-ui.alert>`                |
| Layouts               | `<x-layouts::dev>` → `resources/views/layouts/dev.blade.php`    |

**Regra prática:** se um grupo de classes ou de HTML se repete **três vezes**, torná-lo num componente.

**Próximo passo:** componentes Blade são estáticos: cada interação exige uma nova página. No [Guia 03.3](03.3-Livewire.md) vemos como o **Livewire** torna componentes interativos sem escrever JavaScript.

## 10. Problemas comuns

| Sintoma | Causa provável | Solução |
|---------|----------------|---------|
| `Unable to locate a class or view for component [badge]` | O ficheiro não está em `resources/views/components/` | Criar com `php artisan make:component Badge --view` |
| A etiqueta `<x-badge>` aparece no HTML sem ser processada | Nome do ficheiro diferente da etiqueta | `StatCard` → `stat-card.blade.php` → `<x-stat-card>` (minúsculas e hífens) |
| `Undefined variable $header` | O slot é usado sem `@isset` e não foi passado | Usar `@isset($header)` ou passar o slot |
| O componente ignora a `class` que passei | Falta `{{ $attributes… }}` no elemento raiz | Acrescentar `{{ $attributes->class([…]) }}` |
| Os atributos aparecem duplicados | `{{ $attributes }}` usado em dois sítios | Usar apenas num elemento |
| Passei `color="$cor"` e aparece o texto `$cor` | Falta o `:` | Escrever `:color="$cor"` |
| A cor da variante não aparece | Classe montada por partes (`bg-{{ $c }}-100`) | Escrever as classes completas (Guia 03.1, secção 8.3) |
| `Unable to locate a class or view for component [ui.alert]` | O ficheiro não está em `components/ui/` | `php artisan make:component Ui/Alert --view` |
| `Undefined variable $slot` | Componente usado como página (`view('…')`) | Componentes usam-se com `<x-…>` |
| As alterações não aparecem | Vistas compiladas em cache | `php artisan view:clear` |
