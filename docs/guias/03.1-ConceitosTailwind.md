## Antes de começar

### Como utilizar este guia

Este guia foi escrito para ser seguido **de forma autónoma**, depois da aula.

- Seguir as secções **pela ordem indicada**. Cada secção acrescenta um bloco à mesma página.
- Em cada secção: **acrescentar** o código à página, **guardar**, **observar** o resultado no navegador e fazer o **exercício**.
- No fim de cada secção existe um bloco **Verificar**.
- Os ficheiros novos são criados com **comandos Artisan**. Não criar ficheiros manualmente.
- Se algo não funcionar, consultar a secção [11. Problemas comuns](#11-problemas-comuns).

### Pré-requisitos

- Guias **01** e **02** concluídos.
- Serviços Docker em execução:

  ```bash
  docker compose up -d
  ```

- Aplicação em execução num terminal próprio (deixar aberto durante todo o guia):

  ```bash
  composer run dev
  ```

  O `composer run dev` inclui o **Vite**, que regenera o CSS sempre que guardamos um ficheiro.

- Os comandos `php artisan …` são executados noutro terminal, **na raiz do projeto**.

### Âmbito

Neste guia trabalhamos **apenas** Tailwind, numa página de testes. **Não** alteramos o Fortify, as páginas de autenticação nem criamos os layouts da aplicação (isso é o Guia 03.5).

### Ferramentas do navegador

Vamos usar as **ferramentas de programador** (_DevTools_):

| Ação                          | Windows / Linux         | macOS          |
|-------------------------------|-------------------------|----------------|
| Abrir as DevTools             | `F12` ou `Ctrl+Shift+I` | `Cmd+Option+I` |
| Modo responsivo (telemóvel)   | `Ctrl+Shift+M`          | `Cmd+Shift+M`  |

## 1. Preparar as páginas de testes

⏱ ~5 min

### 1.1. O layout das páginas de testes

Vamos criar um layout **mínimo** que será partilhado pelas páginas de testes dos guias 03.1 a 03.4:

```bash
php artisan make:view layouts.dev
```

Resultado esperado:

```text
INFO  View [resources/views/layouts/dev.blade.php] created successfully.
```

**Apagar todo o conteúdo** do ficheiro e substituir por:

```blade
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
    <head>
        @include('partials.head')
    </head>
    <body class="min-h-screen bg-stone-50 font-sans text-stone-800 antialiased">
        <nav class="border-b border-stone-200 bg-white">
            <div class="mx-auto flex max-w-5xl items-center gap-6 px-4 py-3 text-sm">
                <span class="font-semibold text-stone-900">Laboratório</span>

                @foreach (['tailwind' => 'Tailwind', 'components' => 'Componentes', 'livewire' => 'Livewire', 'flux' => 'Flux'] as $name => $label)
                    @if (Route::has('dev.'.$name))
                        <a href="{{ route('dev.'.$name) }}" class="text-stone-600 hover:text-stone-900">{{ $label }}</a>
                    @endif
                @endforeach
            </div>
        </nav>

        <main class="mx-auto max-w-5xl px-4 py-10">
            {{ $slot }}
        </main>

        <flux:toast.group>
            <flux:toast />
        </flux:toast.group>

        @fluxScripts
    </body>
</html>
```

Pontos a notar:

- `@include('partials.head')` carrega o `<head>` do Starter Kit, que inclui o **Vite** (`@vite`) e, por isso, o nosso CSS.
- O menu só mostra as páginas que **já existem** (`Route::has`). Vai crescendo à medida que avançamos nos guias.
- `{{ $slot }}` é onde aparece o conteúdo de cada página.
- O `<flux:toast>` e o `@fluxScripts` só serão necessários no Guia 03.4. Ficam já aqui para não voltarmos a editar o layout.

### 1.2. A página de testes

```bash
php artisan make:view dev.tailwind
```

Resultado esperado:

```text
INFO  View [resources/views/dev/tailwind.blade.php] created successfully.
```

Apagar o conteúdo gerado (uma citação) e substituir por:

```blade
<x-layouts::dev title="Tailwind">
    <div class="space-y-16">

        <h1 class="text-3xl font-bold tracking-tight text-stone-900">Laboratório de Tailwind</h1>
        
        <section class="space-y-6">
            <h2 class="text-xl font-semibold text-stone-900">Primeiro Teste</h2>
            <div class="flex items-center gap-4">
                <button>Sem classes</button>
                <button class="rounded-lg bg-brand-600 px-4 py-2 text-sm font-semibold text-white hover:bg-brand-700 cursor-pointer">
                    Com classes
                </button>
            </div>
        </section>

        {{-- As secções seguintes são acrescentadas aqui, uma a seguir à outra --}}

    </div>
</x-layouts::dev>
```

`<x-layouts::dev>` usa o ficheiro `resources/views/layouts/dev.blade.php` como layout. Voltaremos a este mecanismo no Guia 03.2.

### 1.3. A rota de testes

Em `routes/web.php`, **depois** da rota `dev.login`, acrescentar:

```php
// Páginas de testes (guias 03.1 a 03.4): apenas em desenvolvimento (APP_ENV=local)
if (app()->isLocal()) {
    Route::prefix('dev')->name('dev.')->group(function () {
        Route::view('tailwind', 'dev.tailwind')->name('tailwind');
    });
}
```

A rota só é registada com `APP_ENV=local`. Em produção, o endereço não existe (404).

Abrir: http://localhost:8000/dev/tailwind

### Verificar

```bash
php artisan route:list --name=dev.tailwind
```

- A rota `dev.tailwind` aparece listada.
- O navegador mostra o título **Laboratório de Tailwind** e uma barra com o link "Tailwind".

## 2. O tema da marca (`brand`)

⏱ ~5 min

No Tailwind 4 **não existe** `tailwind.config.js`: o tema define-se **em CSS**, no ficheiro `resources/css/app.css`.

Abrir `resources/css/app.css`. Reparar em duas coisas:

```css
@import 'tailwindcss';
@source '../views';
```

- `@import 'tailwindcss'` carrega o Tailwind;
- `@source '../views'` indica onde procurar nomes de classes. É por isso que as classes escritas nas vistas Blade entram no CSS final.

Dentro do bloco `@theme { … }` existente, **acrescentar** a paleta da marca:

```css
    --color-brand-50: #f4f7f2;
    --color-brand-100: #e6ede0;
    --color-brand-200: #cddcc2;
    --color-brand-300: #aac29b;
    --color-brand-400: #82a271;
    --color-brand-500: #5f8350;
    --color-brand-600: #4a6b3d;
    --color-brand-700: #3c5632;
    --color-brand-800: #32462b;
    --color-brand-900: #2b3b25;
    --color-brand-950: #16200f;
```

Cada variável `--color-brand-600` gera **automaticamente** classes: `bg-brand-600`, `text-brand-600`, `border-brand-600`, `ring-brand-600`, …

> Se o ficheiro já tiver estas linhas, **não duplicar**.

### Exercício

Alterar temporariamente `--color-brand-600` para `#2563eb` (azul), guardar e ver que o botão mudar de cor. **Repor** o valor `#4a6b3d` no fim.

### Verificar

- O `app.css` tem 11 variáveis `--color-brand-*` dentro do `@theme`.

## 3. Utility-first, espaçamento e tipografia

⏱ ~10 min

Em Tailwind **não escrevemos CSS**. Combinamos classes pequenas, cada uma com **uma** responsabilidade.

Acrescentar na página, no lugar do comentário (e manter o comentário por baixo):

```blade
<section class="space-y-6">
    <h2 class="text-xl font-semibold text-stone-900">3. Utility-first, espaçamento e tipografia</h2>

    <div class="flex flex-wrap items-start gap-6">
        <div class="bg-brand-100"><div class="bg-brand-300 p-2">p-2</div></div>
        <div class="bg-brand-100"><div class="bg-brand-300 p-4">p-4</div></div>
        <div class="bg-brand-100"><div class="bg-brand-300 p-8">p-8</div></div>
        <div class="bg-brand-100"><div class="bg-brand-300 px-8 py-2">px-8 py-2</div></div>
    </div>

    <div class="space-y-2">
        <div class="bg-stone-200 p-2">space-y-2</div>
        <div class="bg-stone-200 p-2">espaço entre cada filho</div>
        <div class="bg-stone-200 p-2">do contentor</div>
    </div>

    <div class="grid gap-4 md:grid-cols-3">
        <p class="text-left text-sm">text-sm text-left</p>
        <p class="text-center text-xl font-semibold uppercase tracking-widest">centrado</p>
        <p class="text-right text-3xl font-bold italic">text-3xl</p>
    </div>

    <p class="max-w-md truncate">truncate: um texto muito comprido que não cabe numa só linha e é cortado com reticências.</p>
</section>
```

### Cada classe é uma regra CSS

| Classe               | CSS equivalente                                  |
|----------------------|--------------------------------------------------|
| `rounded-lg`         | `border-radius: 0.5rem;`                         |
| `bg-brand-600`       | `background-color: #4a6b3d;`                     |
| `px-4`               | `padding-left: 1rem; padding-right: 1rem;`       |
| `py-2`               | `padding-top: 0.5rem; padding-bottom: 0.5rem;`   |
| `text-sm`            | `font-size: 0.875rem;`                           |
| `font-semibold`      | `font-weight: 600;`                              |
| `hover:bg-brand-700` | cor de fundo mais escura ao passar o rato        |

### A escala de espaçamento

**1 unidade = 0,25 rem = 4 px.** Por isso `p-4` = 16 px e `p-8` = 32 px.

| Prefixo      | Significado                                         |
|--------------|-----------------------------------------------------|
| `p-` / `m-`  | _padding_ (interior) / _margin_ (exterior)          |
| `x` / `y`    | eixo horizontal / vertical: `px-`, `py-`, `mx-`, `my-` |
| `t` `r` `b` `l` | lado: `pt-`, `mr-`, …                            |
| `gap-`       | espaço entre filhos de um `flex`/`grid`             |
| `space-y-`   | espaço vertical entre filhos                        |

> Os títulos (`<h1>`, `<h2>`) **não têm estilo por omissão**: o Tailwind remove-o (_preflight_). Todo o tamanho e peso é pedido por classes.

### Como o CSS é gerado

1. O Tailwind **lê o texto** dos ficheiros (os definidos com `@source`).
2. Procura nomes de classes.
3. Gera **apenas** o CSS das classes encontradas.

Nas DevTools, separador **Elements**, selecionar um elemento e ver as regras em **Styles**.

### Exercício

1. Passar o rato sobre um elemento `p-4` nas DevTools e confirmar os **16 px**.
2. Acrescentar `uppercase tracking-wider` ao botão "Com classes".

### Verificar

- O primeiro botão tem o aspeto padrão do navegador; o segundo é verde, arredondado, e escurece no `hover`.
- Os quatro quadrados têm espaços interiores diferentes.

## 4. Cores, bordas, raios e sombras

⏱ ~7 min

Acrescentar:

```blade
<section class="space-y-6">
    <h2 class="text-xl font-semibold text-stone-900">4. Cores e caixas</h2>

    <div class="grid grid-cols-6 gap-1 text-center text-xs">
        <div class="bg-brand-100 py-4">100</div>
        <div class="bg-brand-300 py-4">300</div>
        <div class="bg-brand-500 py-4 text-white">500</div>
        <div class="bg-brand-600 py-4 text-white">600</div>
        <div class="bg-brand-800 py-4 text-white">800</div>
        <div class="bg-brand-950 py-4 text-white">950</div>
    </div>

    <div class="rounded-lg bg-brand-900 p-6">
        <div class="flex flex-wrap gap-3 text-sm font-medium">
            <span class="rounded bg-white px-3 py-2 text-brand-900">bg-white</span>
            <span class="rounded bg-white/50 px-3 py-2 text-brand-900">bg-white/50</span>
            <span class="rounded bg-white/10 px-3 py-2 text-white">bg-white/10</span>
        </div>
    </div>

    <div class="flex flex-wrap items-center gap-4">
        <div class="size-16 rounded-none bg-brand-600"></div>
        <div class="size-16 rounded-md bg-brand-600"></div>
        <div class="size-16 rounded-2xl bg-brand-600"></div>
        <div class="size-16 rounded-full bg-brand-600"></div>
    </div>

    <div class="grid gap-6 sm:grid-cols-3">
        <div class="rounded-xl border border-stone-200 bg-white p-4 shadow-xs">shadow-xs</div>
        <div class="rounded-xl border border-stone-200 bg-white p-4 shadow-md">shadow-md</div>
        <div class="rounded-xl border border-stone-200 bg-white p-4 shadow-xl">shadow-xl</div>
    </div>

    <div class="max-w-md rounded-xl border border-stone-200 bg-white p-6 shadow-sm">
        <h3 class="text-lg font-semibold text-stone-900">Rosaceae</h3>
        <p class="mt-1 text-sm text-stone-600">Este é o padrão base dos cartões do FloraHub.</p>
    </div>
</section>
```

Pontos importantes:

- Cada família de cor tem tons de `50` (mais claro) a `950` (mais escuro).
- O **prefixo** escolhe a propriedade: `bg-` (fundo), `text-` (texto), `border-` (borda), `ring-` (anel), `from-`/`to-` (gradiente).
- `/50` é a **opacidade**: `bg-white/50` é branco a 50%.
- `size-16` = `w-16 h-16`.
- Indicar sempre a **cor da borda** (`border border-stone-200`): em Tailwind 4 a cor por omissão é `currentColor`.

### Exercício

1. Trocar a cor do cartão: fundo `bg-brand-50` e borda `border-brand-200`.
2. Acrescentar ao cartão `ring-2 ring-brand-500`. Qual a diferença visual para uma `border`?

### Verificar

- Os seis quadrados vão do verde claro ao quase preto.
- Os quatro quadrados vão de cantos retos a círculo.
- As três sombras aumentam.

## 5. Flexbox e Grid

⏱ ~8 min

Acrescentar:

```blade
<section class="space-y-6">
    <h2 class="text-xl font-semibold text-stone-900">5. Flexbox e Grid</h2>

    <p class="text-sm text-stone-600"><code>flex</code> põe os filhos em linha; <code>justify-between</code> + <code>items-center</code>:</p>
    <div class="flex h-20 items-center justify-between rounded-lg bg-stone-100 px-4">
        <span class="font-semibold">FloraHub</span>
        <span class="text-sm text-stone-600">Menu</span>
    </div>

    <p class="text-sm text-stone-600"><code>justify-*</code> (eixo principal) e <code>items-*</code> (eixo cruzado):</p>
    <div class="grid grid-cols-3 gap-2 text-sm">
        <div class="flex h-24 items-start justify-start rounded bg-stone-100 p-2"><span class="rounded bg-brand-300 px-3 py-1">start</span></div>
        <div class="flex h-24 items-center justify-center rounded bg-stone-100 p-2"><span class="rounded bg-brand-300 px-3 py-1">center</span></div>
        <div class="flex h-24 items-end justify-end rounded bg-stone-100 p-2"><span class="rounded bg-brand-300 px-3 py-1">end</span></div>
    </div>

    <p class="text-sm text-stone-600"><code>flex-col</code> e <code>flex-1</code> (um item ocupa o espaço restante):</p>
    <div class="flex gap-4">
        <div class="flex w-40 flex-col gap-2 rounded-lg bg-stone-100 p-2 text-sm">
            <span class="rounded bg-brand-300 px-3 py-1">Item 1</span>
            <span class="rounded bg-brand-300 px-3 py-1">Item 2</span>
        </div>
        <div class="flex flex-1 items-center rounded-lg bg-brand-100 px-4 text-sm">flex-1</div>
    </div>

    <p class="text-sm text-stone-600"><code>grid grid-cols-4</code> e <code>col-span-2</code>:</p>
    <div class="grid grid-cols-4 gap-4 text-center">
        <div class="col-span-2 rounded bg-brand-500 p-4 text-white">col-span-2</div>
        <div class="rounded bg-brand-300 p-4">1</div>
        <div class="rounded bg-brand-300 p-4">2</div>
        <div class="rounded bg-brand-300 p-4">3</div>
        <div class="rounded bg-brand-300 p-4">4</div>
        <div class="col-span-2 rounded bg-brand-500 p-4 text-white">col-span-2</div>
    </div>
</section>
```

Regra para decorar (numa `flex-row`):

- `justify-*` → eixo **principal** (horizontal);
- `items-*` → eixo **cruzado** (vertical);
- `flex-col` **troca** os eixos.

| Flex                                  | Grid                                      |
|---------------------------------------|-------------------------------------------|
| Uma dimensão (linha **ou** coluna)    | Duas dimensões (linhas **e** colunas)     |
| Menus, cabeçalhos, botões lado a lado | Grelhas de cartões, layouts de página     |

### Exercício

1. Construir um cartão com **avatar à esquerda e texto à direita**: `flex items-center gap-3`, avatar `size-10 rounded-full bg-brand-600` e, ao lado, dois parágrafos (nome e email).
2. Mudar a última grelha para `grid-cols-3`. O que acontece aos `col-span-2`?

### Verificar

- O cabeçalho tem o texto nos extremos, centrado na vertical.
- Os três exemplos colocam o rótulo em cima-esquerda, ao centro e em baixo-direita.

## 6. Design responsivo

⏱ ~6 min

O Tailwind é **_mobile-first_**:

- classe **sem prefixo** → aplica-se a **todos** os tamanhos;
- classe **com prefixo** (`md:`) → aplica-se **a partir** desse tamanho.

| Prefixo | A partir de |
|---------|-------------|
| (nenhum)| 0 px        |
| `sm:`   | 640 px      |
| `md:`   | 768 px      |
| `lg:`   | 1024 px     |
| `xl:`   | 1280 px     |

Acrescentar:

```blade
<section class="space-y-6">
    <h2 class="text-xl font-semibold text-stone-900">6. Design responsivo</h2>

    <p class="rounded-lg bg-stone-900 px-4 py-3 font-mono text-sm text-white">
        Largura atual:
        <span class="sm:hidden">base (&lt; 640)</span>
        <span class="hidden sm:inline md:hidden">sm (≥ 640)</span>
        <span class="hidden md:inline lg:hidden">md (≥ 768)</span>
        <span class="hidden lg:inline xl:hidden">lg (≥ 1024)</span>
        <span class="hidden xl:inline">xl (≥ 1280)</span>
    </p>

    <div class="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-4">
        <div class="rounded-xl border border-stone-200 bg-white p-4">Cartão 1</div>
        <div class="rounded-xl border border-stone-200 bg-white p-4">Cartão 2</div>
        <div class="rounded-xl border border-stone-200 bg-white p-4">Cartão 3</div>
        <div class="rounded-xl border border-stone-200 bg-white p-4">Cartão 4</div>
    </div>

    <div class="flex flex-col gap-2 md:flex-row md:items-center md:justify-between">
        <p class="font-semibold">Coluna no telemóvel, linha a partir de md</p>
        <button class="rounded-lg bg-brand-600 px-4 py-2 text-sm font-semibold text-white">Ação</button>
    </div>

    <p class="rounded-lg bg-amber-100 p-3 text-sm text-amber-800 md:hidden">Só em ecrãs pequenos (<code>md:hidden</code>).</p>
    <p class="hidden rounded-lg bg-sky-100 p-3 text-sm text-sky-800 md:block">Só a partir de md (<code>hidden md:block</code>).</p>
</section>
```

Como ver o resultado:

1. Abrir as DevTools e ativar o **modo responsivo**.
2. Alterar a largura e observar o rótulo "Largura atual" e a grelha.

A grelha lê-se assim:

```text
grid-cols-1 sm:grid-cols-2 lg:grid-cols-4
│           │               └─ a partir de 1024 px: 4 colunas
│           └─ a partir de 640 px: 2 colunas
└─ por omissão (telemóvel): 1 coluna
```

> **Erro frequente:** `sm:` **não** significa "só em telemóveis". Significa "a partir de 640 px". Escrever primeiro o estilo para telemóvel e acrescentar prefixos para ecrãs maiores.

### Exercício

1. Fazer a grelha ter **3 colunas** a partir de `md`.
2. Explicar o que faz `hidden md:flex` num menu: o que se vê abaixo e acima de 768 px?

### Verificar

- Com a janela estreita: cartões empilhados e só a mensagem âmbar.
- Com a janela larga: 4 cartões lado a lado e só a mensagem azul.
- O rótulo "Largura atual" muda ao redimensionar.

## 7. Estados, `group` e `peer`

⏱ ~5 min

Uma **variante** é um prefixo que faz a classe aplicar-se só numa condição: `hover:`, `focus:`, `active:`, `disabled:`, `odd:`, … Já usámos `md:`, que também é uma variante.

Acrescentar:

```blade
<section class="space-y-6">
    <h2 class="text-xl font-semibold text-stone-900">7. Estados, group e peer</h2>

    <div class="flex flex-wrap items-center gap-4">
        <button class="rounded-lg bg-brand-600 px-4 py-2 text-sm font-semibold text-white transition hover:-translate-y-0.5 hover:shadow-lg active:translate-y-0 active:scale-95">
            hover + active
        </button>
        <button class="rounded-lg bg-brand-600 px-4 py-2 text-sm font-semibold text-white disabled:cursor-not-allowed disabled:opacity-50" disabled>
            disabled
        </button>
        <input type="text" placeholder="Clicar aqui (focus)"
               class="w-64 rounded-lg border border-stone-300 px-3 py-2 text-sm placeholder:text-stone-400 focus:border-brand-500 focus:outline-hidden focus:ring-2 focus:ring-brand-500/40">
    </div>

    <div class="grid gap-4 sm:grid-cols-2">
        <a href="#" class="group block rounded-xl border border-stone-200 bg-white p-5 transition hover:border-brand-500 hover:shadow-md">
            <h3 class="font-semibold text-stone-800 group-hover:text-brand-700">Rosaceae</h3>
            <p class="mt-1 text-sm text-stone-500">Passar o rato no cartão.</p>
            <span class="mt-3 inline-block text-sm font-medium text-brand-700 opacity-0 transition group-hover:opacity-100">Ver detalhes →</span>
        </a>

        <div class="space-y-3 rounded-xl border border-stone-200 bg-white p-5">
            <label class="flex items-center gap-2 text-sm">
                <input type="checkbox" class="peer size-4 accent-brand-600">
                <span class="text-stone-500 peer-checked:font-semibold peer-checked:text-brand-700">Aceito os termos</span>
            </label>

            <label class="flex cursor-pointer items-center gap-3 rounded-lg border border-stone-200 p-3 text-sm has-checked:border-brand-500 has-checked:bg-brand-50">
                <input type="radio" name="plano" class="accent-brand-600">
                <span>has-checked: o contentor reage</span>
            </label>
        </div>
    </div>
</section>
```

Pontos importantes:

- Sem `transition`, a mudança de `hover:` é **instantânea**.
- `focus:outline-hidden` remove o contorno por omissão, por isso é **obrigatório** dar outro indicador de foco (`focus:ring-2`). Sem foco visível, o teclado fica inutilizável.
- **`group`**: o **pai** tem `group`; os filhos reagem com `group-hover:`.
- **`peer`**: um **irmão anterior** tem `peer`; o seguinte reage com `peer-checked:`.
- `has-checked:` é a alternativa: o **contentor** reage ao que tem dentro.
- As variantes **empilham-se**: `md:hover:bg-brand-700`.

2. Trocar a ordem do `<input class="peer">` e do `<span>`. Porque deixa de funcionar?

### Verificar

- Ao passar o rato no cartão, o título muda de cor e aparece "Ver detalhes →".
- Ao marcar a caixa, o texto fica verde e a negrito.
- O campo mostra um anel verde ao receber o foco.

## 8. Modo escuro, valores arbitrários e uma armadilha

⏱ ~5 min

### 8.1. Modo escuro

O prefixo `dark:` aplica a classe quando o modo escuro está ativo. No `resources/css/app.css` do Starter Kit existe:

```css
@custom-variant dark (&:where(.dark, .dark *));
```

Significa: `dark:` aplica-se **dentro de qualquer elemento com a classe `dark`**. Normalmente essa classe está no `<html>` (é o Flux que a coloca, conforme a preferência do sistema).

Acrescentar:

```blade
<section class="space-y-6">
    <h2 class="text-xl font-semibold text-stone-900">8. Escuro, arbitrários e armadilha</h2>

    <div class="dark">
        <div class="rounded-xl border border-stone-200 bg-white p-6 text-stone-800 dark:border-stone-700 dark:bg-stone-900 dark:text-stone-100">
            <p class="font-semibold">Dentro de &lt;div class="dark"&gt;</p>
            <p class="text-sm text-stone-500 dark:text-stone-400">Classes <code>dark:</code> ativas porque um ascendente tem a classe <code>dark</code>.</p>
        </div>
    </div>
```

> Se o sistema operativo estiver em **modo escuro**, o Flux coloca `dark` no `<html>` e **todos** os blocos com `dark:` ficam escuros. É normal. Os layouts de dashboard do FloraHub são **apenas em modo claro**, por isso não usam `dark:`.

### 8.2. Valores arbitrários

Quando a escala não tem o valor de que precisamos, usamos **parênteses retos**. Continuar, dentro da mesma `<section>`:

```blade
    <div class="grid grid-cols-[8rem_1fr_auto] gap-2 text-center text-sm">
        <div class="rounded bg-brand-300 p-2">8rem</div>
        <div class="rounded bg-brand-200 p-2">1fr</div>
        <div class="rounded bg-brand-300 p-2 text-[13px]">text-[13px]</div>
    </div>
```

Dentro de `[ ]`, os espaços escrevem-se com `_`. Usar com moderação: se o valor se repete, deve passar a fazer parte do tema.

### 8.3. A armadilha das classes dinâmicas

O Tailwind **lê o texto dos ficheiros**. Não executa PHP. Se o nome **completo** da classe não aparecer escrito, a classe **não é gerada**. Continuar e **fechar** a secção:

```blade
    @php
        $color = 'slate';
        $isError = true;
    @endphp

    <div class="rounded-lg p-4 bg-{{ $color }}-100 text-{{ $color }}-800">ERRADO: classe montada em PHP</div>

    <div class="{{ $isError ? 'bg-rose-100 text-rose-800' : 'bg-brand-100 text-brand-800' }} rounded-lg p-4">
        CERTO: classes completas, escolhidas por uma condição
    </div>
</section>
```

O primeiro bloco aparece **sem cor**. Nas DevTools, o atributo `class` tem o nome completo da classe, mas **não existe CSS** para ela: o Tailwind nunca encontrou esse texto, por extenso, em nenhum ficheiro.

> O Tailwind procura nomes de classes em **todos** os ficheiros do projeto (incluindo Markdown). Se o nome completo aparecer escrito noutro sítio, a classe é gerada e a armadilha deixa de se notar. Por isso o exemplo usa uma cor (`slate`) que não é usada em mais lado nenhum.

Alternativa elegante: a diretiva `@class` (Blade):

```blade
<div @class(['bg-rose-100' => $isError, 'bg-brand-100' => ! $isError])>
```

## 10. Resumo

| Conceito                      | Classes / ideia                                              |
|-------------------------------|--------------------------------------------------------------|
| Utility-first                 | Uma classe = uma regra CSS. Sem CSS próprio                  |
| Escala de espaçamento         | 1 unidade = 0,25 rem. `p-4`, `mx-auto`, `gap-6`, `space-y-2` |
| Tipografia                    | `text-sm` `font-semibold` `truncate`                         |
| Cores                         | `bg-brand-600` `text-white` `bg-white/50`                    |
| Caixa                         | `rounded-xl border border-stone-200 shadow-sm`               |
| Flex                          | `flex items-center justify-between gap-4`                    |
| Grid                          | `grid grid-cols-1 md:grid-cols-3 gap-6`                      |
| Responsivo                    | _mobile-first_: `md:` = "a partir de 768 px"                 |
| Estados                       | `hover:` `focus:` `active:` `disabled:`                      |
| `group` / `peer` / `has-*`    | reagir ao estado de outro elemento                           |
| Modo escuro                   | `dark:` dentro de um elemento com a classe `dark`            |
| Valores arbitrários           | `grid-cols-[8rem_1fr_auto]`                                  |
| Tema                          | `@theme` em `resources/css/app.css`                          |
| Armadilha                     | Nunca montar nomes de classes com PHP                        |

**Próximo passo:** o mesmo grupo de classes aparece repetido muitas vezes. No [Guia 03.2](03.2-ComponentesBlade.md) aprendemos a reutilizá-lo com **componentes Blade**.

## 11. Problemas comuns

| Sintoma | Causa provável | Solução |
|---------|----------------|---------|
| A página aparece **sem estilos** | O Vite não está em execução | Confirmar que `composer run dev` está a correr. Em alternativa, `npm run build` |
| `404` em `/dev/tailwind` | A rota não existe ou `APP_ENV` não é `local` | Rever `routes/web.php` e o `.env`; `php artisan route:list --name=dev.tailwind` |
| `View [dev.tailwind] not found` | A vista foi criada noutro sítio | Confirmar `resources/views/dev/tailwind.blade.php` (criada com `php artisan make:view dev.tailwind`) |
| `Unable to locate a class or view for component [layouts::dev]` | O layout não existe ou está noutra pasta | Criar com `php artisan make:view layouts.dev` (secção 1.1) |
| Aparece uma **citação** no topo da página | O conteúdo gerado pelo `make:view` não foi apagado | Apagar o conteúdo original do ficheiro |
| As cores `brand-*` não aparecem | Variáveis não adicionadas ao `@theme` | Rever a secção 2 e guardar `resources/css/app.css` |
| Uma classe nova não faz nada | Erro de escrita ou nome montado em PHP | Rever o nome da classe (p. ex. `justify-centre`) e a secção 8.3 |
| `sm:`/`md:` parecem não funcionar | Janela larga demais | Usar o modo responsivo das DevTools; o prefixo significa "a partir de" |
| `group-hover:` não faz nada | O pai não tem a classe `group` | Acrescentar `group` ao ascendente |
| `peer-checked:` não faz nada | O `peer` não é irmão **anterior** | Colocar o `peer` **antes** e no mesmo nível |
| Tudo aparece escuro | O sistema está em modo escuro e o Flux ativa `dark` | Normal. Ver nota da secção 8.1 |
| As alterações numa vista não aparecem | Vistas compiladas em cache | `php artisan view:clear` e recarregar a página |
