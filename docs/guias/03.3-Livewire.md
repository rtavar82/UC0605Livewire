# Guia 03.3 — Livewire e componentes Livewire

Os componentes Blade (Guia 03.2) produzem HTML **estático**: para mostrar algo diferente, o navegador tem de pedir uma página nova.

O **Livewire** permite escrever componentes **interativos** em PHP, sem escrever JavaScript: clicar num botão, filtrar uma lista em tempo real ou validar um formulário sem recarregar a página.

Neste guia construímos, na página de testes `/dev/livewire`, quatro pequenas demonstrações:

| Demonstração              | Conceito principal                                   |
|---------------------------|------------------------------------------------------|
| Contador                  | propriedades públicas e ações (`wire:click`)         |
| Pesquisa em tempo real    | `wire:model.live` e propriedades computadas          |
| Formulário com validação  | `wire:submit`, `#[Validate]`, `wire:loading`         |
| Componente filho + eventos| `<livewire:…>`, `wire:key`, `dispatch` e `#[On]`     |

A teoria de apoio está no tutorial [Livewire](../tutorials/04.Livewire.md).

No final teremos:

```text
resources/views/
│
├── pages/dev/
│   └── ⚡livewire.blade.php        → página de testes (componente de página completa)
│
└── components/
    └── ⚡species-like.blade.php    → componente filho (botão "gosto")
```

## Antes de começar

### Como utilizar este guia

Este guia foi escrito para ser seguido **de forma autónoma**, depois da aula.

- Seguir as secções **pela ordem indicada**. Cada secção acrescenta código ao **mesmo** ficheiro.
- Os ficheiros novos são criados com **comandos Artisan**. Não criar ficheiros manualmente.
- No fim de cada secção existe um bloco **Verificar**.
- Se algo não funcionar, consultar a secção [8. Problemas comuns](#8-problemas-comuns).

### Pré-requisitos

- **Guias 03.1 e 03.2** concluídos (`layouts/dev.blade.php` e o grupo de rotas `dev.`).
- Serviços Docker e aplicação em execução:

  ```bash
  docker compose up -d
  composer run dev
  ```

- Os comandos `php artisan …` são executados noutro terminal, **na raiz do projeto**.

### Blade ou Livewire?

| Componente Blade (03.2)                    | Componente Livewire (03.3)                          |
|--------------------------------------------|-----------------------------------------------------|
| Apresentação reutilizável                  | Apresentação **com estado e comportamento**         |
| Sem estado: recebe dados e mostra-os       | Tem **propriedades** que persistem entre pedidos    |
| Usa-se com `<x-nome>`                      | Usa-se com `<livewire:nome />` ou como página       |
| Não responde a cliques                     | Responde a cliques, teclas e formulários (`wire:*`) |

Regra prática: **só usar Livewire quando é preciso interação**. Um botão ou um cartão estáticos continuam a ser componentes Blade.

### Como funciona (resumo)

```text
1. A página é gerada no servidor (HTML normal).
2. O utilizador clica em  wire:click="increment".
3. O navegador envia um pedido  POST /livewire-…/update  com a ação e o estado atual.
4. O servidor executa  increment()  e volta a gerar o HTML do componente.
5. O Livewire compara o HTML novo com o antigo e atualiza só o que mudou.
```

Todo o código corre no **servidor**, em PHP. Não escrevemos JavaScript.

## 1. Criar a página Livewire

⏱ ~5 min

### 1.1. Criar o componente

```bash
php artisan make:livewire pages::dev.livewire
```

Resultado esperado:

```text
INFO  Livewire component [resources/views/pages/dev/⚡livewire.blade.php] created successfully.
```

O ficheiro (o prefixo `⚡` identifica um componente Livewire de **ficheiro único**) tem duas partes:

- **Em cima**, entre `<?php` e `?>`: a classe PHP (propriedades e métodos);
- **Em baixo**: a vista Blade, com **um único elemento raiz**.

Substituir **todo** o conteúdo por:

```blade
<?php

use Livewire\Attributes\Layout;
use Livewire\Attributes\Title;
use Livewire\Component;

new #[Layout('layouts::dev')] #[Title('Livewire')] class extends Component {
    //
};
?>

<div class="space-y-16">
    <h1 class="text-3xl font-bold tracking-tight text-stone-900">Laboratório de Livewire</h1>

    {{-- As secções seguintes são acrescentadas aqui --}}
</div>
```

- `#[Layout('layouts::dev')]` → usa o nosso layout de testes (o conteúdo vai para o `{{ $slot }}`);
- `#[Title('Livewire')]` → chega ao layout como `$title`.

### 1.2. A rota

Em `routes/web.php`, no grupo `dev.`, acrescentar:

```php
Route::prefix('dev')->name('dev.')->group(function () {
    Route::view('tailwind', 'dev.tailwind')->name('tailwind');
    Route::view('components', 'dev.components')->name('components');
    Route::livewire('livewire', 'pages::dev.livewire')->name('livewire');
});
```

`Route::livewire()` liga o URL diretamente ao componente, **sem controlador**. É a convenção do Starter Kit e do FloraHub.

### Verificar

```bash
php artisan route:list --name=dev.livewire
```

- A rota aparece listada.
- http://localhost:8000/dev/livewire mostra o título e a barra tem agora o link **Livewire**.

## 2. Contador: propriedades e ações

⏱ ~8 min

Uma **propriedade pública** é o estado do componente. Um **método público** é uma ação que a vista pode chamar.

Na parte PHP, substituir `//` por:

```php
    public int $count = 0;

    public function increment(): void
    {
        $this->count++;
    }

    public function decrement(): void
    {
        $this->count--;
    }
```

Na vista, no lugar do comentário, acrescentar:

```blade
    <section class="space-y-4">
        <h2 class="text-xl font-semibold text-stone-900">2. Contador</h2>

        <div class="flex items-center gap-4">
            <x-button variant="secondary" wire:click="decrement">−</x-button>
            <span class="w-12 text-center text-3xl font-bold text-stone-900">{{ $count }}</span>
            <x-button wire:click="increment">+</x-button>
        </div>
    </section>
```

(Reutilizamos o `x-button` do Guia 03.2. O atributo `wire:click` passa pelo `$attributes` até ao `<button>`.)

Pontos importantes:

- `wire:click="increment"` chama o método `increment()` **no servidor**.
- `{{ $count }}` lê a propriedade. Depois da ação, o Livewire atualiza o número sem recarregar a página.
- A propriedade tem **tipo** (`int`). O Livewire usa-o para converter valores.

### Ver o que acontece

1. Abrir as DevTools, separador **Network**, filtro **Fetch/XHR**.
2. Clicar em `+`.
3. Aparece um pedido `POST` para `/livewire-…/update`. No **Payload**, procurar `calls` → `method: "increment"`; na **Response**, procurar `effects` → `html`.

O URL da página **não mudou** e a página **não recarregou**.

> **Atenção:** todas as propriedades públicas são visíveis (e alteráveis) pelo navegador. **Nunca** guardar nelas dados secretos, e **nunca** confiar nelas sem validar/autorizar no servidor. Voltaremos a isto no Guia 05.

### Exercício

1. Acrescentar um botão "Repor" que volta a `0`. Pista: `$this->reset('count')`.
2. Impedir que o contador fique abaixo de `0`.

### Verificar

- Os botões `+` e `−` alteram o número sem recarregar a página.
- No separador Network aparece um pedido por clique.

## 3. Pesquisa em tempo real: `wire:model.live`

⏱ ~10 min

`wire:model` liga um campo a uma propriedade. Por omissão, o valor só é enviado ao servidor **na próxima ação**. Com `.live`, é enviado a **cada tecla**.

| Diretiva                              | Quando envia ao servidor                   |
|---------------------------------------|--------------------------------------------|
| `wire:model="x"`                      | só quando há outra ação (ex.: submeter)    |
| `wire:model.live="x"`                 | a cada alteração (cada tecla)              |
| `wire:model.live.debounce.300ms="x"`  | 300 ms depois de o utilizador parar        |
| `wire:model.blur="x"`                 | quando o campo perde o foco                |

### 3.1. A lógica

Na parte PHP, acrescentar o `use` e as novas peças:

```php
use Livewire\Attributes\Computed;
```

```php
    public string $search = '';

    #[Computed]
    public function results(): array
    {
        $species = [
            'Rosa canina', 'Rosa gallica', 'Malus domestica', 'Fragaria vesca',
            'Lavandula angustifolia', 'Quercus robur', 'Olea europaea',
        ];

        return array_values(array_filter(
            $species,
            fn (string $name) => str_contains(mb_strtolower($name), mb_strtolower($this->search)),
        ));
    }
```

- `#[Computed]` cria uma **propriedade computada**: um valor calculado a partir do estado, acedido como `$this->results`. Não é guardado no navegador.

### 3.2. A vista

Acrescentar, depois da secção do contador:

```blade
    <section class="space-y-4">
        <h2 class="text-xl font-semibold text-stone-900">3. Pesquisa em tempo real</h2>

        <div class="grid gap-4 sm:grid-cols-2">
            <div class="space-y-1">
                <label class="text-sm font-medium">wire:model.live.debounce.300ms</label>
                <input type="text" wire:model.live.debounce.300ms="search" placeholder="Escrever, p. ex. rosa"
                       class="w-full rounded-lg border border-stone-300 px-3 py-2 text-sm focus:border-brand-500 focus:outline-hidden focus:ring-2 focus:ring-brand-500/40">
                <p class="text-sm text-stone-500">Valor no servidor: <code>{{ $search }}</code></p>
            </div>

            <ul class="divide-y divide-stone-200 rounded-lg border border-stone-200 bg-white text-sm">
                @forelse ($this->results as $name)
                    <li class="px-4 py-2 italic">{{ $name }}</li>
                @empty
                    <li class="px-4 py-2 text-stone-500">Sem resultados.</li>
                @endforelse
            </ul>
        </div>
    </section>
```

### Exercício

1. Trocar `wire:model.live.debounce.300ms` por `wire:model` (sem `.live`). O que mudou? Quando é que a lista se atualiza?
2. Sem `debounce` (`wire:model.live`), quantos pedidos aparecem no separador Network ao escrever "rosa"?

### Verificar

- Ao escrever, a lista filtra-se e o valor `{{ $search }}` acompanha o campo.
- Ao apagar tudo, aparecem as sete espécies.

## 4. Formulário com validação

⏱ ~10 min

### 4.1. A lógica

Acrescentar o `use`:

```php
use Livewire\Attributes\Validate;
```

e as peças:

```php
    #[Validate('required|min:3|max:50')]
    public string $suggestion = '';

    #[Validate('required|email')]
    public string $email = '';

    public ?string $saved = null;

    public function save(): void
    {
        $this->validate();

        usleep(800_000); // simula um processamento lento (só para ver o estado de carregamento)

        $this->saved = $this->suggestion;
        $this->reset('suggestion', 'email');
    }
```

- `#[Validate('…')]` associa regras de validação à propriedade (as mesmas regras do Laravel).
- `$this->validate()` valida **todas** as propriedades com `#[Validate]`. Se falhar, interrompe a ação e as mensagens ficam disponíveis na vista.
- `$this->reset(...)` repõe os valores iniciais.
- `usleep` só existe para tornar o estado de carregamento visível. **Nunca** fazer isto numa aplicação real.

### 4.2. A vista

```blade
    <section class="space-y-4">
        <h2 class="text-xl font-semibold text-stone-900">4. Formulário com validação</h2>

        <form wire:submit="save" class="max-w-md space-y-4 rounded-xl border border-stone-200 bg-white p-6 shadow-sm">
            <div class="space-y-1">
                <label for="suggestion" class="text-sm font-medium">Sugerir uma espécie</label>
                <input id="suggestion" type="text" wire:model="suggestion"
                       class="w-full rounded-lg border border-stone-300 px-3 py-2 text-sm focus:border-brand-500 focus:outline-hidden focus:ring-2 focus:ring-brand-500/40">
                @error('suggestion')
                    <p class="text-sm text-red-600">{{ $message }}</p>
                @enderror
            </div>

            <div class="space-y-1">
                <label for="email" class="text-sm font-medium">O seu email</label>
                <input id="email" type="text" wire:model="email"
                       class="w-full rounded-lg border border-stone-300 px-3 py-2 text-sm focus:border-brand-500 focus:outline-hidden focus:ring-2 focus:ring-brand-500/40">
                @error('email')
                    <p class="text-sm text-red-600">{{ $message }}</p>
                @enderror
            </div>

            <div class="flex items-center gap-3">
                <x-button type="submit" wire:loading.attr="disabled" wire:target="save">Enviar</x-button>
                <span wire:loading wire:target="save" class="text-sm text-stone-500">A guardar…</span>
            </div>

            @if ($saved)
                <x-ui.alert type="success" title="Recebido">Sugestão <strong>{{ $saved }}</strong> enviada.</x-ui.alert>
            @endif
        </form>
    </section>
```

Pontos importantes:

- `wire:submit="save"` chama `save()` e **impede** o envio normal do formulário (sem recarregar a página).
- `wire:model` (sem `.live`) → os valores só viajam quando o formulário é submetido. É o comportamento certo para formulários.
- `@error('campo') … $message … @enderror` mostra a mensagem de validação desse campo.
- `wire:loading` mostra o elemento **enquanto** há um pedido pendente; `wire:target="save"` limita-o à ação `save`.
- `wire:loading.attr="disabled"` desativa o botão durante o pedido (evita duplo clique).
- Reutilizámos `x-button` e `x-ui.alert` do Guia 03.2: componentes Blade **dentro** de um componente Livewire.

> O `type="text"` no email é intencional: assim o navegador não valida o formato e podemos ver a validação **do servidor**.

### Exercício

1. Submeter o formulário vazio. Que mensagens aparecem? Em que idioma? (A tradução é matéria do Guia 10.)
2. Escrever "ab" na sugestão e um email válido. Qual a mensagem?
3. Acrescentar `wire:model.blur="email"` e `updatedEmail()` com `$this->validateOnly('email')` para validar o email assim que o campo perde o foco.

### Verificar

- Formulário vazio → duas mensagens a vermelho, **sem** recarregar a página.
- Dados válidos → botão desativado e "A guardar…" durante ~1 s; depois, o alerta verde e os campos vazios.

## 5. Componente filho e eventos

⏱ ~10 min

Um componente pode conter **outros componentes Livewire**. Cada um tem o seu próprio estado. Comunicam por **eventos**.

### 5.1. Criar o componente filho

```bash
php artisan make:livewire species-like
```

Resultado esperado:

```text
INFO  Livewire component [resources/views/components/⚡species-like.blade.php] created successfully.
```

Sem o prefixo `pages::`, o componente é criado em `resources/views/components/`. Substituir **todo** o conteúdo por:

```blade
<?php

use Livewire\Component;

new class extends Component {
    public string $species = '';

    public bool $liked = false;

    public function toggle(): void
    {
        $this->liked = ! $this->liked;

        $this->dispatch('species-liked', species: $this->species, liked: $this->liked);
    }
};
?>

<button type="button" wire:click="toggle"
        @class([
            'rounded-full border px-3 py-1 text-xs font-medium transition',
            'border-brand-600 bg-brand-600 text-white' => $liked,
            'border-stone-300 bg-white text-stone-700 hover:bg-stone-50' => ! $liked,
        ])>
    {{ $liked ? '♥ Gosto' : '♡ Gostar' }}
</button>
```

- `$species` é recebido do pai; `$liked` é o estado **próprio** deste filho.
- `$this->dispatch('species-liked', …)` emite um **evento** com dados, que sobe até ao pai.

### 5.2. Usar o filho e escutar o evento

Na página (`⚡livewire.blade.php`), acrescentar o `use`:

```php
use Livewire\Attributes\On;
```

e as peças na classe:

```php
    public int $likes = 0;

    #[On('species-liked')]
    public function onLiked(string $species, bool $liked): void
    {
        $this->likes += $liked ? 1 : -1;
    }
```

Alterar a lista da secção 3 para incluir o filho em cada linha:

```blade
            <ul class="divide-y divide-stone-200 rounded-lg border border-stone-200 bg-white text-sm">
                @forelse ($this->results as $name)
                    <li class="flex items-center justify-between px-4 py-2" wire:key="{{ $name }}">
                        <span class="italic">{{ $name }}</span>
                        <livewire:species-like :species="$name" :key="$name" />
                    </li>
                @empty
                    <li class="px-4 py-2 text-stone-500">Sem resultados.</li>
                @endforelse
            </ul>
```

E acrescentar, dentro da `<section>` da secção 3, **antes** do `</section>`, o total:

```blade
    <p class="text-sm text-stone-600">Total de "gostos": <strong class="text-brand-700">{{ $likes }}</strong></p>
```

Pontos importantes:

- `<livewire:species-like :species="$name" />` insere o componente filho. O `:` passa um valor PHP, tal como nos componentes Blade.
- Em **listas**, cada filho precisa de uma chave única: `:key="$name"`. Sem ela, o Livewire pode misturar o estado entre filhos quando a lista muda.
- `#[On('species-liked')]` faz o método do pai executar quando o evento chega. Os argumentos nomeados do `dispatch` ligam-se aos parâmetros do método.

```text
filho:  toggle() ──dispatch('species-liked')──►  pai:  onLiked()  →  $likes++
```

### Exercício

1. Marcar "Gostar" em duas espécies e depois **filtrar** a lista com a pesquisa. O estado do filho mantém-se? E o total?
2. Remover o `:key` do filho. Repetir o passo anterior. O que acontece de errado?

### Verificar

- Cada linha tem um botão "♡ Gostar" que alterna para "♥ Gosto" (verde).
- O total no pai aumenta e diminui conforme os botões.
- No separador Network, cada clique envia um pedido por **componente** (filho) e outro para o pai.

## 7. Resumo

| Conceito                    | Exemplo                                                              |
|-----------------------------|----------------------------------------------------------------------|
| Criar página                | `php artisan make:livewire pages::dev.livewire`                      |
| Criar componente            | `php artisan make:livewire species-like`                             |
| Rota de página              | `Route::livewire('livewire', 'pages::dev.livewire')`                 |
| Layout e título             | `#[Layout('layouts::dev')]` `#[Title('Livewire')]`                   |
| Estado                      | `public int $count = 0;`                                             |
| Ação                        | `public function increment()` + `wire:click="increment"`             |
| Ligar campo                 | `wire:model`, `wire:model.live`, `wire:model.live.debounce.300ms`    |
| Valor calculado             | `#[Computed]` → `$this->results`                                     |
| Validação                   | `#[Validate('required|min:3')]`, `$this->validate()`, `@error`       |
| Formulário                  | `wire:submit="save"`                                                 |
| Carregamento                | `wire:loading`, `wire:target`, `wire:loading.attr="disabled"`        |
| Usar componente filho       | `<livewire:species-like :species="$name" :key="$name" />`            |
| Eventos                     | `$this->dispatch('evento', dado: $x)` e `#[On('evento')]`            |

**Próximo passo:** já sabemos estilizar (Tailwind), reutilizar (Blade) e dar interatividade (Livewire). No [Guia 03.4](03.4-Flux.md) vemos o **Flux UI**: uma biblioteca de componentes já prontos (botões, campos, modais, _toasts_) que usa tudo isto.

## 8. Problemas comuns

| Sintoma | Causa provável | Solução |
|---------|----------------|---------|
| `Unable to find component: [pages::dev.livewire]` | O ficheiro não está em `resources/views/pages/dev/` | Criar com `php artisan make:livewire pages::dev.livewire` |
| `Component not found: [species-like]` | O ficheiro não está em `resources/views/components/` | `php artisan make:livewire species-like` |
| Aparece uma citação no meio da página | O conteúdo gerado não foi apagado | Substituir o conteúdo (secção 1.1) |
| O clique não faz nada | Erro de escrita em `wire:click` ou método inexistente | Ver o separador Console e `storage/logs/laravel.log` |
| `Livewire only supports one HTML element per component` / `Multiple root elements` | A vista tem mais do que um elemento raiz | Envolver tudo num único `<div>` |
| `Property [$x] not found on component` | A propriedade não está declarada como `public` | Declarar `public string $x = '';` |
| A pesquisa só filtra depois de outra ação | Falta `.live` | Usar `wire:model.live.debounce.300ms` |
| As mensagens de validação não aparecem | Falta `@error('campo')` ou o nome não coincide com a propriedade | Rever o nome do campo |
| Os botões "gosto" misturam o estado ao filtrar | Falta `:key` no filho | Acrescentar `:key="$name"` |
| `Call to undefined method …::increment()` | A ação está fora da classe ou não é `public` | Rever a parte PHP do ficheiro |
| `419 Page Expired` | A sessão expirou | Recarregar a página |
| Página sem estilos | O Vite não está em execução | `composer run dev` ou `npm run build` |
