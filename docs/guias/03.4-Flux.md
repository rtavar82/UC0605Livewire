# Guia 03.4 — Exemplos de Flux UI

Nos guias anteriores aprendemos a estilizar (Tailwind), a reutilizar (componentes Blade) e a dar interatividade (Livewire). O **Flux UI** junta tudo isto numa biblioteca de componentes **já prontos**: botões, campos de formulário, modais, menus, _toasts_, tabelas, …

O Flux vem instalado com o Starter Kit. As páginas de autenticação e de definições do FloraHub já o usam. Neste guia construímos a página de testes `/dev/flux` com os componentes que mais vamos usar:

| Secção | Componentes                                                                    |
|--------|--------------------------------------------------------------------------------|
| 2      | `flux:button`, `flux:icon`                                                     |
| 3      | `flux:input`, `flux:textarea`, `flux:select`, `flux:checkbox`, `flux:radio`, `flux:switch` |
| 4      | `flux:badge`, `flux:callout`, `Flux::toast()`                                  |
| 5      | `flux:modal`, `flux:dropdown`, `flux:menu`, `flux:tooltip`                     |
| 6      | `flux:heading`, `flux:text`, `flux:separator`, `flux:avatar`, `flux:table`     |

A teoria de apoio está no tutorial [Flux UI](../tutorials/05.Flux.md).

No final teremos:

```text
resources/views/pages/dev/
└── ⚡flux.blade.php        → página de testes (componente Livewire de página completa)
```

## Antes de começar

### Como utilizar este guia

Este guia foi escrito para ser seguido **de forma autónoma**, depois da aula.

- Seguir as secções **pela ordem indicada**. Cada secção acrescenta código ao **mesmo** ficheiro.
- O ficheiro novo é criado com um **comando Artisan**.
- No fim de cada secção existe um bloco **Verificar**.
- Se algo não funcionar, consultar a secção [10. Problemas comuns](#10-problemas-comuns).

### Pré-requisitos

- **Guias 03.1, 03.2 e 03.3** concluídos (precisamos de `layouts/dev.blade.php` com o `<flux:toast />` e o `@fluxScripts`, do grupo de rotas `dev.` e do Livewire).
- Serviços Docker e aplicação em execução:

  ```bash
  docker compose up -d
  composer run dev
  ```

- Os comandos `php artisan …` são executados noutro terminal, **na raiz do projeto**.

### O que é o Flux?

Os componentes Flux usam-se como `<flux:nome>`. Por baixo, são componentes Blade (Guia 03.2) estilizados com Tailwind (Guia 03.1), e muitos funcionam com `wire:*` do Livewire (Guia 03.3).

```blade
<flux:button variant="primary" icon="plus">Novo</flux:button>
```

### Flux gratuito e Flux Pro

O Flux tem componentes **gratuitos** e **Pro** (pagos).

**No FloraHub usamos apenas os gratuitos.** Os principais:

| Gratuitos (usamos)                                                                          | Pro (**não** usamos)                         |
|---------------------------------------------------------------------------------------------|----------------------------------------------|
| `button`, `input`, `textarea`, `select`, `checkbox`, `radio`, `switch`, `field`, `label`, `error` | `date-picker`, `calendar`, `time-picker`  |
| `modal`, `dropdown`, `menu`, `tooltip`, `toast`, `callout`, `badge`, `avatar`               | `tabs`, `accordion`, `autocomplete`, `editor` |
| `heading`, `text`, `separator`, `card`, `table`, `icon`, `navbar`, `sidebar`                | `command`, `chart`, `pillbox`, `calendar`    |

> Se um componente do site oficial tiver a etiqueta **Pro**, não o usar.

## 1. Criar a página

⏱ ~5 min

```bash
php artisan make:livewire pages::dev.flux
```

Resultado esperado:

```text
INFO  Livewire component [resources/views/pages/dev/⚡flux.blade.php] created successfully.
```

Substituir **todo** o conteúdo do ficheiro por:

```blade
<?php

use Flux\Flux;
use Livewire\Attributes\Layout;
use Livewire\Attributes\Title;
use Livewire\Component;

new #[Layout('layouts::dev')] #[Title('Flux')] class extends Component {
    //
};
?>

<div class="space-y-16">
  <script>
        window.Flux.applyAppearance = () => document.documentElement.classList.remove('dark');
        window.Flux.applyAppearance();
    </script>
    <flux:heading size="xl" level="1">Laboratório de Flux</flux:heading>

    {{-- As secções seguintes são acrescentadas aqui --}}
</div>
```

Em `routes/web.php`, no grupo `dev.`, acrescentar:

```php
    Route::livewire('flux', 'pages::dev.flux')->name('flux');
```

(A página é Livewire porque os formulários, modais e _toasts_ do Flux funcionam com o Livewire.)

### Verificar

- http://localhost:8000/dev/flux mostra o título.
- A barra superior tem agora os quatro links: **Tailwind**, **Componentes**, **Livewire**, **Flux**.

## 2. Botões e ícones

⏱ ~6 min

Acrescentar:

```blade
<section class="space-y-4">
    <flux:heading size="lg">2. Botões e ícones</flux:heading>

    <div class="flex flex-wrap items-center gap-3">
        <flux:button>Predefinido</flux:button>
        <flux:button variant="primary">Primário</flux:button>
        <flux:button variant="filled">Preenchido</flux:button>
        <flux:button variant="outline">Contorno</flux:button>
        <flux:button variant="ghost">Fantasma</flux:button>
        <flux:button variant="danger">Perigo</flux:button>
    </div>

    <div class="flex flex-wrap items-center gap-3">
        <flux:button size="sm" variant="primary">Pequeno</flux:button>
        <flux:button variant="primary">Normal</flux:button>
        <flux:button variant="primary" icon="plus">Com ícone</flux:button>
        <flux:button variant="outline" icon-trailing="arrow-right">Seguinte</flux:button>
        <flux:button variant="ghost" icon="trash" size="sm" aria-label="Remover" />
        <flux:button href="{{ route('dev.tailwind') }}" variant="outline">É um link</flux:button>
        <flux:button variant="primary" disabled>Desativado</flux:button>
    </div>

    <div class="flex items-center gap-4 text-stone-600">
        <flux:icon.home />
        <flux:icon.magnifying-glass />
        <flux:icon.check-circle class="text-brand-600" />
        <flux:icon.exclamation-triangle class="size-8 text-amber-500" />
    </div>
</section>
```

Pontos importantes:

- O botão `variant="primary"` aparece **verde**: o Flux usa a cor de _acento_ (`--color-accent`), que o `resources/css/app.css` do FloraHub liga à nossa paleta `brand`. É o Tailwind (03.1) a mandar no aspeto do Flux.
- Com `href`, o botão torna-se um `<a>` (tal como o nosso `x-button` do 03.2).
- Um botão **só com ícone** não tem texto: acrescentar sempre `aria-label` (acessibilidade).
- Os ícones são os [Heroicons](https://heroicons.com). O nome do ícone é o nome do Heroicon: `<flux:icon.home />` ou `icon="home"` nos botões.
- Classes Tailwind podem ser acrescentadas a qualquer componente Flux (`class="size-8 text-amber-500"`).

### Exercício

1. Trocar o ícone do botão "Com ícone" por outro do site heroicons.com (p. ex. `pencil-square`).
2. Nas DevTools, inspecionar um botão `primary`. Que variável CSS define a cor de fundo?

### Verificar

- Seis botões com estilos diferentes; o primário é verde.
- O botão "É um link" navega para `/dev/tailwind`.

## 3. Formulários

⏱ ~10 min

O Flux simplifica os campos: com `label=` o componente gera a etiqueta, o campo **e** a mensagem de erro automaticamente.

### 3.1. A lógica

Na parte PHP, acrescentar o `use`:

```php
use Livewire\Attributes\Validate;
```

e substituir `//` por:

```php
    #[Validate('required|min:3|max:50')]
    public string $commonName = '';

    #[Validate('required')]
    public string $family = '';

    #[Validate('required|min:10')]
    public string $notes = '';

    #[Validate('required|in:full,partial,shade')]
    public string $sun = 'partial';

    public bool $notify = true;

    #[Validate('accepted')]
    public bool $agree = false;

    public function save(): void
    {
        $this->validate();

        Flux::toast(heading: 'Guardado', text: "A planta «{$this->commonName}» foi registada.", variant: 'success');

        $this->reset('commonName', 'family', 'notes', 'agree');
    }
```

(É a mesma ideia do formulário do Guia 03.3. A novidade é `Flux::toast()`, que veremos na secção 4.)

### 3.2. A vista

```blade
<section class="space-y-4">
    <flux:heading size="lg">3. Formulários</flux:heading>

    <form wire:submit="save" class="max-w-lg space-y-6 rounded-xl border border-stone-200 bg-white p-6 shadow-sm">
        <flux:input wire:model="commonName" label="Nome comum" placeholder="Ex.: Rosa-brava" />

        <flux:select wire:model="family" label="Família" placeholder="Escolher família…">
            <flux:select.option value="rosaceae">Rosaceae</flux:select.option>
            <flux:select.option value="lamiaceae">Lamiaceae</flux:select.option>
            <flux:select.option value="fagaceae">Fagaceae</flux:select.option>
        </flux:select>

        <flux:textarea wire:model="notes" label="Notas" rows="3" description="Mínimo 10 caracteres." />

        <flux:radio.group wire:model="sun" label="Exposição solar">
            <flux:radio value="full" label="Sol direto" />
            <flux:radio value="partial" label="Meia-sombra" />
            <flux:radio value="shade" label="Sombra" />
        </flux:radio.group>

        <flux:switch wire:model="notify" label="Receber lembretes de rega" />

        <flux:checkbox wire:model="agree" label="Confirmo que os dados estão corretos" />

        <div class="flex gap-3">
            <flux:button type="submit" variant="primary">Guardar</flux:button>
            <flux:button type="reset" variant="ghost">Limpar</flux:button>
        </div>
    </form>
</section>
```

Pontos importantes:

- `wire:model="commonName"` liga o campo à propriedade (Guia 03.3). Não é preciso escrever `@error`: o Flux mostra a mensagem de erro por baixo do campo.
- `label=` e `description=` geram as etiquetas e o texto de ajuda.
- `flux:select.option`, `flux:radio` e `flux:checkbox` são os elementos filhos.
- `<flux:radio.group>` agrupa os botões de opção; o valor escolhido vai para `$sun`.

### Forma longa (quando precisamos de controlo)

A forma abreviada resolve quase tudo. Se precisarmos de organizar a etiqueta e o erro à nossa maneira, existe a forma longa:

```blade
<flux:field>
    <flux:label>Nome comum</flux:label>
    <flux:input wire:model="commonName" />
    <flux:error name="commonName" />
</flux:field>
```

### Exercício

1. Submeter o formulário vazio. Que campos mostram erro? Como se distinguem visualmente?
2. Preencher corretamente e submeter. O que acontece aos campos?
3. Escrever o campo "Nome comum" na forma longa.

### Verificar

- Formulário vazio → mensagens de erro a vermelho junto de cada campo.
- Formulário correto → os campos limpam-se (o _toast_ só aparece, de forma visível, depois da secção 4).

## 4. Feedback: badges, callouts e toasts

⏱ ~7 min

Acrescentar:

```blade
<section class="space-y-4">
    <flux:heading size="lg">4. Badges, callouts e toasts</flux:heading>

    <div class="flex flex-wrap items-center gap-2">
        <flux:badge color="green">Ativa</flux:badge>
        <flux:badge color="red">Removida</flux:badge>
        <flux:badge color="amber">Pendente</flux:badge>
        <flux:badge color="sky" size="sm">Info</flux:badge>
        <flux:badge color="zinc" icon="lock-closed">Privada</flux:badge>
    </div>

    <div class="space-y-3">
        <flux:callout icon="information-circle" heading="Informação" text="Um aviso neutro, com ícone e título." />
        <flux:callout variant="success" icon="check-circle" heading="Guardado" text="A operação foi concluída." />
        <flux:callout variant="warning" icon="exclamation-triangle" heading="Atenção" text="Esta ação não pode ser desfeita." />
        <flux:callout variant="danger" icon="x-circle" heading="Erro" text="Não foi possível guardar." />
    </div>

    <div class="flex flex-wrap gap-3">
        <flux:button wire:click="toastSuccess">Toast de sucesso</flux:button>
        <flux:button wire:click="toastWarning">Toast de aviso</flux:button>
        <flux:button wire:click="toastDanger">Toast de erro</flux:button>
    </div>
</section>
```

E, na parte PHP, os três métodos:

```php
    public function toastSuccess(): void
    {
        Flux::toast(heading: 'Sucesso', text: 'A família foi guardada.', variant: 'success');
    }

    public function toastWarning(): void
    {
        Flux::toast(heading: 'Atenção', text: 'Verifique os dados.', variant: 'warning');
    }

    public function toastDanger(): void
    {
        Flux::toast(text: 'Não foi possível guardar.', variant: 'danger');
    }
```

Pontos importantes:

- Os _toasts_ são mostrados pelo componente `<flux:toast />`, que **já está no layout** `layouts/dev.blade.php` (Guia 03.1). Sem ele, `Flux::toast()` não mostra nada.
- `Flux::toast()` chama-se **no PHP** (numa ação Livewire). É assim que as páginas de definições do Starter Kit mostram "Profile updated".
- O `@fluxScripts` do layout carrega o JavaScript de que os modais, menus e _toasts_ precisam.

### Exercício

1. Repetir o submit do formulário da secção 3 com dados válidos. Agora o _toast_ "Guardado" aparece.
2. Experimentar `duration: 10000` (milissegundos) em `Flux::toast()`.

### Verificar

- Cinco _badges_ coloridos e quatro _callouts_ (neutro, verde, âmbar, vermelho).
- Cada botão mostra um _toast_ no canto do ecrã, que desaparece sozinho.

## 5. Sobreposições: modal, menu e tooltip

⏱ ~8 min

### 5.1. Modal de confirmação

Um modal tem um **nome**. O `flux:modal.trigger` abre-o; o `flux:modal.close` fecha-o.

Acrescentar:

```blade
<section class="space-y-4">
    <flux:heading size="lg">5. Modal, menu e tooltip</flux:heading>

    <div class="flex flex-wrap items-center gap-3">
        <flux:modal.trigger name="remove-plant">
            <flux:button variant="danger" icon="trash">Remover planta</flux:button>
        </flux:modal.trigger>

        <flux:dropdown>
            <flux:button icon-trailing="chevron-down">Opções</flux:button>

            <flux:menu>
                <flux:menu.item icon="eye">Ver</flux:menu.item>
                <flux:menu.item icon="pencil-square">Editar</flux:menu.item>
                <flux:menu.separator />
                <flux:menu.item icon="trash" variant="danger">Remover</flux:menu.item>
            </flux:menu>
        </flux:dropdown>

        <flux:tooltip content="Os tooltips aparecem ao passar o rato">
            <flux:button icon="question-mark-circle" variant="ghost" aria-label="Ajuda" />
        </flux:tooltip>
    </div>

    <flux:modal name="remove-plant" class="min-w-[22rem]">
        <div class="space-y-6">
            <div>
                <flux:heading size="lg">Remover planta?</flux:heading>
                <flux:text class="mt-2">Esta ação não pode ser desfeita.</flux:text>
            </div>

            <div class="flex gap-2">
                <flux:spacer />
                <flux:modal.close>
                    <flux:button variant="ghost">Cancelar</flux:button>
                </flux:modal.close>
                <flux:button variant="danger" wire:click="removePlant">Remover</flux:button>
            </div>
        </div>
    </flux:modal>
</section>
```

E, na parte PHP:

```php
    public function removePlant(): void
    {
        Flux::modal('remove-plant')->close();

        Flux::toast(heading: 'Removida', text: 'A planta foi removida.', variant: 'danger');
    }
```

Pontos importantes:

- `flux:modal.trigger name="remove-plant"` abre o modal com o mesmo `name`. **Não precisa de JavaScript nem de propriedade Livewire.**
- `flux:modal.close` fecha o modal ao clicar.
- `Flux::modal('remove-plant')->close()` (e `->show()`) fecha/abre o modal a partir do PHP. Usamo-lo quando a ação do servidor termina.
- `flux:dropdown` + `flux:menu` criam um menu suspenso. O primeiro filho é o _trigger_ (o botão).
- `flux:spacer` empurra os elementos seguintes para a direita (é um `flex-1`).
- O modal de confirmação do FloraHub (Guia 06) usa exatamente esta mecânica.

### Exercício

1. Trocar `<flux:modal …>` por `<flux:modal … flyout>`. O que muda? (É o formato usado nos _drawers_ da gestão de famílias.)
2. Acrescentar `flux:tooltip` a um dos botões do menu.

### Verificar

- O botão vermelho abre o modal; "Cancelar" fecha-o; "Remover" fecha-o **e** mostra um _toast_ vermelho.
- O botão "Opções" abre um menu; o ícone `?` mostra um _tooltip_.

```blade
        <flux:table.columns>
            <flux:table.column>Família</flux:table.column>
            <flux:table.column>Espécies</flux:table.column>
            <flux:table.column>Estado</flux:table.column>
        </flux:table.columns>

        <flux:table.rows>
            <flux:table.row>
                <flux:table.cell variant="strong">Rosaceae</flux:table.cell>
                <flux:table.cell>12</flux:table.cell>
                <flux:table.cell><flux:badge size="sm" color="green">Ativa</flux:badge></flux:table.cell>
            </flux:table.row>
            <flux:table.row>
                <flux:table.cell variant="strong">Lamiaceae</flux:table.cell>
                <flux:table.cell>7</flux:table.cell>
                <flux:table.cell><flux:badge size="sm" color="red">Removida</flux:badge></flux:table.cell>
            </flux:table.row>
        </flux:table.rows>
    </flux:table>

```

Pontos importantes:

- `flux:heading`, `flux:subheading` e `flux:text` aplicam tipografia consistente (tamanhos, cores e modo escuro) sem escrevermos classes.
- `flux:separator` aceita texto no meio.
- `flux:avatar name="…"` mostra as iniciais; `color="auto"` escolhe uma cor a partir do nome.
- A tabela é composta por `columns`, `rows`, `row` e `cell`. A gestão de famílias (Guia 05) usa-a.

## 7. Personalizar com Tailwind

⏱ ~3 min

Os componentes Flux aceitam `class` como qualquer componente Blade (Guia 03.2) e as classes são **acrescentadas**:

```blade
<flux:button variant="primary" class="w-full">Largura total</flux:button>
<flux:input class="max-w-xs" />
<flux:modal class="md:w-lg" />
```

Regras práticas:

- **Layout e tamanho** (`w-*`, `max-w-*`, `mt-*`, `flex-1`) → seguro. É o uso normal.
- **Cores e aspeto interno** → preferir as _props_ do componente (`variant`, `color`, `size`) e o tema (`--color-accent`), em vez de sobrepor classes.
- **Não** reescrever o interior de componentes do Flux. Quando o Flux não chega, criar um componente Blade nosso (Guia 03.2), eventualmente **a usar** componentes Flux por dentro.

### Flux ou componente nosso?

| Preciso de…                                         | Usar                                              |
|-----------------------------------------------------|---------------------------------------------------|
| Botão, campo, modal, menu, tabela genéricos         | **Flux**                                          |
| Um bloco específico do FloraHub (cartão de espécie) | **Componente Blade nosso** (`x-species-card`)     |
| Um layout de página                                 | **Layout Blade nosso** (`x-layouts::…`)           |
| Interação com o servidor (CRUD, filtros)            | **Livewire** (com Flux dentro)                    |

### Exercício

Fazer um botão primário com largura total e um campo `max-w-xs`, e inspecionar nas DevTools onde foram parar as classes.

## 9. Resumo

| Conceito                  | Exemplo                                                                   |
|---------------------------|---------------------------------------------------------------------------|
| Usar um componente        | `<flux:button variant="primary" icon="plus">Novo</flux:button>`           |
| Ícones                    | `<flux:icon.home />`, `icon="trash"`, `icon-trailing="arrow-right"`       |
| Campo com etiqueta e erro | `<flux:input wire:model="x" label="Nome" />`                              |
| Forma longa               | `flux:field` + `flux:label` + `flux:input` + `flux:error`                 |
| Selecionar                | `flux:select` + `flux:select.option`, `flux:radio.group`, `flux:checkbox` |
| Estado                    | `flux:badge color="green"`, `flux:callout variant="success"`              |
| Toast                     | `Flux::toast(heading: …, text: …, variant: 'success')`                    |
| Modal                     | `flux:modal.trigger name="x"` + `flux:modal name="x"` + `flux:modal.close` |
| Modal pelo PHP            | `Flux::modal('x')->show()` / `->close()`                                  |
| Menu                      | `flux:dropdown` + `flux:menu` + `flux:menu.item`                          |
| Tipografia                | `flux:heading`, `flux:subheading`, `flux:text`                            |
| Tabela                    | `flux:table` + `columns` / `rows` / `row` / `cell`                        |
| Personalizar              | `class="w-full"`; cor de acento em `--color-accent`                       |
| Pro                       | **Não usar** (`date-picker`, `tabs`, `accordion`, …)                      |

## 10. Problemas comuns

| Sintoma | Causa provável | Solução |
|---------|----------------|---------|
| `Unable to find component: [pages::dev.flux]` | O ficheiro não está em `resources/views/pages/dev/` | `php artisan make:livewire pages::dev.flux` |
| O botão aparece sem estilos | O Vite não está em execução | `composer run dev` ou `npm run build` |
| O modal/menu/toast não abre | Falta `@fluxScripts` no layout | Rever `layouts/dev.blade.php` (Guia 03.1, secção 1.1) |
| `Flux::toast()` não mostra nada | Falta `<flux:toast />` no layout | Rever `layouts/dev.blade.php` |
| `Class "Flux" not found` / `Flux::` indefinido | Falta o `use Flux\Flux;` | Acrescentar no topo da parte PHP |
| `Unable to locate a class or view for component [flux::…]` | Componente **Pro** ou nome errado | Confirmar o nome em fluxui.dev e a etiqueta **Pro** |
| O formulário recarrega a página | Falta `wire:submit="save"` | Rever o `<form>` |
| Não aparecem erros de validação | Falta `#[Validate]`/`$this->validate()` ou o nome não coincide | Rever a propriedade e o `wire:model` |
| O modal "Remover" não fecha | Falta `Flux::modal('remove-plant')->close()` ou o nome é diferente | O `name` tem de ser igual em todos os sítios |
| O ícone não aparece | Nome inexistente | Usar o nome exato do Heroicon (heroicons.com) |
| `Multiple root elements` | Mais de um elemento raiz no componente Livewire | Envolver tudo num único `<div>` |
